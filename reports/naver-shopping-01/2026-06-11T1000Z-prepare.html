01 무엇을 점검했나
러기지 태그 / 캐리어 이름표 키워드 — 범용 수하물 태그(commodity)와 커스텀/퍼스널라이즈드 세그먼트 간 차별화 가능성. 클라우드에서 접근 가능한 일반 지식 기반 키워드 가설 정리. 실검은 로컬 Naver Shopping 접근 시 실행.
02 이상 여부 · 조치
네이버 쇼핑 IP 차단 지속 (클라우드 접근 불가) — 실검 불가. 키워드 가설 5종 + 차별화 구매 상황 3종 + 테스트 프로토콜을 준비 완료. 로컬 에이전트가 이 준비 문서로 즉시 실행 가능.

  • 상황 1: "해외여행 전 캐리어 분실 방지를 위해 이름표가 필요한 사람" → 실용/긴급 수요
  • 상황 2: "캐리어를 내 스타일로 꾸미고 싶은 사람" → 감성/퍼스널라이즈 수요
  • 상황 3: "여행 선물을 찾는 사람" → 선물 구매 수요
로컬 실행 프로토콜 (나래 에이전트용)

이 섹션은 로컬 나래 에이전트가 Naver Shopping 접근 가능 시 실행할 프로토콜이다.

  1. 각 키워드 그룹 (A~E)에서 대표 1~2개 키워드로 OpenAPI 검색 → total 수치 기록
  2. SearchAd 키워드 도구로 PC + mobile 월간 검색량 확인
  3. Top 10 상품 성격 분류: 글로벌 수입 commodity / 국내 커스텀 / 브랜드 차별화
  4. 그룹 C (커스텀/각인) 또는 D (감성/여행)에서 white-space 확인
  5. 판정 기준 적용:
    • PROMOTE: 커스텀/선물 각도에서 top 10 비어 있고 SearchAd volume 적정 → 다음 단계 진입
    • PIVOT: 차별화 angle 존재하지만 keyword-weak → 구매 상황 재설정
    • HOLD: commodity 포화, 차별화 angle 없음 → 다음 SKU 후보로 이동

이전 맥락: arrival-day-insert 키워드 테스트 → HOLD (buyer intent 약함, generic commodity). 러기지 태그는 더 명확한 구매 상황(분실방지/선물)이 있어 차별화 각도 발견 가능성 더 높음.
