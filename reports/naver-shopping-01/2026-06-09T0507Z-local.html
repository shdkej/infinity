클릭 트렌드 포맷 해결 → 트래블러스노트만 견고한 12개월 수요

미해결이던 DataLab getKeywordClickTrend 키워드 파라미터 포맷을 풀었다. 12개월 트렌드를 실측하니, 시드 키워드 중 트래블러스노트만 12/12개월 빈틈 없는 시계열(연말 피크)을 갖고, 구조화 체크리스트·플래너 용어는 대부분 빈 달투성이(저volume)였다.

01 무엇을 했나
04:07Z의 미해결 항목인 클릭 트렌드 keyword 파라미터 포맷을 바운드 프로브로 해결했다. 포맷은 콤마·JSON이 아니라 단일 평문 키워드 + 해당 cid였다. 이어 Core/Niche/앵커 10개 키워드의 12개월 실측 시계열을 수집했다. 네이버쇼핑 검색은 HTTP 418 변화 없음(가용성) — 경쟁 스캔 미실행.
02 핵심 결과
시드 키워드 중 트래블러스노트만 12개월 내내 데이터가 존재(연말 10~1월 피크 = 다이어리·리필 시즌)했다. 구조화 Core 용어(여행체크리스트·패킹리스트·여행준비물·해외여행준비)는 종이 카테고리에서 빈 시계열(네이버가 저volume 달을 숨김)이었다. 04:07Z의 PIVOT 방향이 더 단단해졌다 — 인서트 포맷이 유일한 실수요 앵커.
  1. getKeywordClickTrend 포맷 해결: 단일 평문 keyword + cid 스코프(콤마/JSON 금지) — 04:07Z 미해결 항목 종료
  2. 트래블러스노트(노트/수첩): 12/12개월 시계열, 연말(10~1월) 피크 → 유일한 견고·밀집 여행 앵커
  3. 구조화 Core(여행체크리스트·패킹리스트·여행준비물·해외여행준비): 종이 카테고리에서 빈 시계열(저volume 신호)
  4. 여행플래너·여행계획표: 데이터는 있으나 듬성하고 계절성 스파이크(5월/1월) → 코어 베이스 아닌 시즌·콘텐츠 각도
  5. 네이버쇼핑 공개검색 HTTP 418 지속 → 경쟁 화이트스페이스 스캔 여전히 미실행(정식 verdict 보류)

③ 해석 (단정 아님, 방향성)

  • 시드 키워드 가운데 유일하게 12개월 밀집 시계열을 가진 여행 키워드 = 트래블러스노트. 04:07Z의 "유일한 견고 앵커" 랭크 신호를 시계열 밀도로 독립 재확인.
  • 구조화 "여행 체크리스트/준비물/패킹" Core 용어는 종이 카테고리에서 지속 베이스가 없음(빈 달 또는 thin). → 독립 체크리스트 SKU의 수요 근거가 약함.
  • 여행플래너·여행계획표는 계절성 스파이크(여름 직전 5월, 연초 1월)는 있으나 베이스가 얕다 → 코어 SKU 베이스보다는 시즌 윈도우/콘텐츠 각도로 적합.
  • 종합: PIVOT 방향(인서트 포맷 탑재)이 한 단계 더 단단해짐. 단, 경쟁 화이트스페이스(418)가 미검증이라 PROMOTE/HOLD 정식 판정은 여전히 보류.

④ 가정 원장 (상속 / 변경 / 충돌 / 다음-에이전트 규칙 / 승격 후보)

  • 상속(유지): fit 증거 ≠ 시장 증거; 작은 방향 신호는 PMF/전환/매출 판정 아님(Prelaunch Decision Boundary); 접근 차단(418/Commerce ID)은 가용성 조건이지 수요 신호 아님(Availability And Friction Are Not Value).
  • 변경(이번 런): 04:07Z의 미해결 항목 "클릭 트렌드 포맷"을 해결. 첫 시드 증거를 "카테고리 상대 랭크"에서 "12개월 시계열 밀도"로 보강 — 같은 PIVOT 결론을 다른 측정으로 교차 확인.
  • 충돌: 플랜의 Core 가설(구조화 체크리스트가 핵심 수요)이 시계열로도 약화됨(빈/thin) — 04:07Z 충돌의 연장·강화이지 반전 아님.
  • 다음-에이전트 규칙: (a) DataLab 클릭 트렌드는 키워드 1개=요청 1개, cid 스코프로 호출한다. (b) 값은 자기정규화 지수이니 키워드 간 절대 비교를 하지 말고 월 결측을 저volume 프록시로만 쓴다. (c) 418 해제 또는 로그인 브라우저 경로 전까지 경쟁 verdict를 내지 않는다.
  • MARKETING_LEARNINGS 승격 후보(보류, 단일 런): "DataLab 자기정규화 클릭 지수는 키워드 간 절대 수요 비교용이 아니다 — 월 결측(숨김)을 저volume 프록시로, 시계열 밀도를 지속수요 프록시로 읽어라." 기존 Traffic Source Before Metrics의 '지표 해석 전 분류' 원칙과 동형. 실 경쟁 스캔으로 한 번 더 확인 후에만 승격.
