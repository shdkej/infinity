첫 시드의 키워드/경쟁 검증 플랜을 더 좁혔다

승인된 첫 시드(Travel-Prep System / Travel Scenario Card · Checklist Insert Set)에 대해, 접근이 열리는 즉시 실행할 read-only 검증 플랜을 구매의도 기준으로 더 정밀하게 준비했다. 수요는 아직 미검증.

01 🔍 무엇을 조사/정리했나
기존 measurement path는 계획·체크리스트 키워드와 다이어리·저널 키워드를 한 덩어리로 묶고 있었다. 구조화 준비(prep) SKU에는 다이어리류가 인접 대조 의도일 뿐 핵심 수요가 아니라, 그 검색량을 시드 수요로 세면 과대평가된다. 그래서 볼륨을 읽기 전에 구매의도부터 분리하는 플랜으로 다시 짰다. 이번 런의 단일 접근 프로브는 공개 네이버쇼핑 검색·DataLab 모두 이 호스트에서 차단(가용성 문제이지 수요 신호 아님)임을 재확인했고, 반복 재시도는 하지 않았다.
02 📊 핵심 결과
실행 가능한 키워드/경쟁 검증 플랜을 Naver agent 레포에 신규 산출(keyword-competitor-validation-plan.md). 핵심은 의도 4분할과 PROMOTE/PIVOT/HOLD 판단 규칙이다.
  1. Core 계획/체크리스트 · Niche 시나리오·레이어 · Overlap 패킹굿즈 · Contrast 다이어리(드리프트 방지용)로 키워드 분할.
  2. 여행 다이어리·트래블저널을 핵심 수요 → 대조 의도로 강등(준비형 SKU 수요로 오집계 방지).
  3. 키워드별 read-only 캡처 스키마(12개월 트렌드 방향·인구·경쟁 수·가격대·상위20 포맷·리뷰·white-space)와 중단 조건 포함 스캔 프로토콜.
  4. 방향성만 보는 판단 규칙: 비하락 트렌드 + white space 존재 + 종이/프린터블 마진 → PROMOTE / 수요가 패킹·다이어리에 쏠림 → PIVOT / 하락+포화 → HOLD.
상세 · 가정 원장 · 경계

계승한 기준 (변경 없음)

  • Fit 증거 ≠ 시장 증거 — 이 시드는 lived-friction fit만 있고 수요는 미검증(product-curation.md).
  • 작은/방향성 신호는 PMF·전환율·매출 확정이 아님 — Prelaunch Decision Boundary(MARKETING_LEARNINGS.md).
  • 접근 차단(HTTP 418 / Commerce ID 게이트)은 가용성 조건이지 수요 신호가 아니며 시드를 무효화하지 않음 — Availability And Friction Are Not Value.

이번에 바꾼 것

  • 시드 키워드를 평면 리스트 → 구매의도 4분할(Core/Niche/Overlap/Contrast)로 재구성. 다이어리류를 핵심 수요에서 대조 세트로 강등.

충돌 (플래그)

  • product-curation.md의 기존 measurement path가 다이어리 용어를 같은 시드 리스트에 두었던 것을 대조 의도로 재분류(반전 아닌 정밀화). 해당 한 줄을 이 플랜 참조로 갱신함.

재사용 학습 후보 (단일 런 — 보류)

  • "쇼핑 검색량을 읽기 전에 키워드 구매의도부터 분리하라 — 구조화 준비형 SKU에는 장식형 기록 키워드가 핵심 수요가 아닌 인접 대조 세트다." (source-before-metric 원칙의 변주.) 실제 스캔으로 확인된 뒤에만 승격. MARKETING_LEARNINGS.md는 Virtue 원장이라 여기엔 승격하지 않음.

경계 (read-only)

  • 상품 등록/수정, 가격·배송·재고·옵션, 광고·비용, 고객/주문/환불/정산, 계정·스토어 설정, 공개 발행은 모두 실행 전 action-level 확인 유지. 이번 산출은 계획·문서뿐이며 외부 변경 0.
