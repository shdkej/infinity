다음 개선안 — 실행·예약 전

  1. 새 글보다 대화부터 진행한다. 받은 구체 의견은 질문표가 없어도 후속으로 확인할 조건이 있는지 본다. 신발 댓글에는 “현지 대체가 어려운 건 사이즈 재고 때문인가요, 오래 걸어도 편한 신발을 다시 찾기 어려워서인가요?”처럼 모르는 조건 한 가지만 물을 수 있었다. 아직 보내지 않은 예시다. 반복 감사·할당량 채우기는 제외한다.
  2. 항공 규정 검색을 실제 짐 선택 경험으로 바꾼다. 이번에는 오래된 반입 규정·사례를 반복 읽고 선제 답글 0건으로 끝났다. 최근 ‘가져가서 안 쓴 물건’, ‘두고 가서 아쉬운 물건’ 대화의 전문·댓글을 읽고 새로 보탤 질문·검증 정보가 있는 경우만 2–3건 내에서 참여한다. 개인 경험을 꾸미지 않고 상대 후속 응답으로 효과를 본다.
  3. 중복이면 검증 행동을 바꾼다. 다음 세 루프 후보는 ① 받은 의견·최근 대화 참여 → ② 반응에서 나온 별개의 판단을 담은 원문 1개 → ③ 재관측·후속이다. 추가 글은 새 판단을 줄 때만 선택한다. 현재 경험이 없으면 과거 공개 기록을 시점과 함께 사용하고, 없던 경험은 만들지 않는다. 탐색 목적의 행동 변경은 인과 비교라고 부르지 않는다.
  4. 2시간은 실행·피드백 간격이다. 첫 관측을 게시 후 약 60분으로 맞추고 다음 실행 계획에 24시간 재측정을 포함한다. 1,000회 목표를 유지하면서 새 원문 조회, 답글 조회, 외부 구체 응답, 이어진 대화를 분리한다. ‘실제 변경 노출’과 ‘후속 회수’가 운영 완료 기준이다.
  5. 감독은 단순하게, 마감은 실제 값으로 검사한다. 각 업무의 네 역할 독립·교차 검토가 기록에 반복돼 PRD의 재사용 지침과 어긋났다. SAM의 짧은 판단과 Windows 실행으로 줄이는 것이 우선이다. 보고 전 현재 run ID·KST 날짜·URL·관측 시각·최신 합계·당일 메시지 영수증을 함께 검사하는 자동 보강이 필요하다. 이번에는 누락을 복구했으며 이 자동 검사를 구현한 것은 아니다.

Meta는 답글이 Threads 조회의 거의 절반을 차지하며 대화를 만드는 글이 추천될 가능성이 높다고 설명한다(공식 안내, 2024-10 발표·2025-06 갱신). 대화 참여를 시험할 근거이며 이 계정의 성과 보장은 아니다.

마감 누락 복구

23시 native closeout은 ok를 남겼지만 전날 76회와 20261126T1400Z-final.html을 오늘 보고로 잘못 참조했다. 현재 원장은 running/pending이고 23시 이후 원문 스레드 조회에는 메시지가 없었다. 이번 검토에서 supervisor를 실제 disable하고 당일 run을 복구 시각에 finished로 마감했다. 여섯 task·guard·지표·과거 이력을 보존했다. 새 Threads 브라우저 업무나 다음 날 예약은 실행하지 않았다.

trace의 미지원 task_guard_start_reconciled 유형은 원문·시각을 보존하고 backfill로 정규화했다. 종합 보고, 원장·단일 trace, 원격 main, 최종 Slack 본문을 확인하고 영수증을 같은 run에 남긴다. 이후 자동 재발 방지 검사는 미구현이다.
