핵심 발견
  1. 재현 패턴: 동일 버그가 ops-05 이후에도 W27에서 다시 등록됨. 생성기가 파일을 열기 전 해당 주차 블록이 이미 있는지 확인하지 않고 무조건 append한다는 확신이 높아짐
  2. 수정 옵션 A — replace: 생성 전 WXX 형태의 주차 헤더 존재 여부를 확인하고, 있으면 해당 블록 전체를 새 내용으로 교체. 가장 단순하고 canonical 블록 1개 보장
  3. 수정 옵션 B — role-split: 기존 블록에 type: canonical 태그를, 새 블록에 type: draft 태그를 붙여 공존 허용. 수동 메모를 보존하고 싶은 경우 유리하나, 소비자가 canonical 블록을 선택적으로 읽는 로직 필요
  4. 검증 방법: 기존 주차(예: W27)로 dry-run 후 grep -c "W27" weekly_review.md 결과가 1(또는 canonical 태그 1)인지 확인
  5. 문서화 범위: 생성기 함수 주석 또는 워크플로우 계약 파일에 "동일 주차 재실행 시 기존 블록 replace" 한 줄 추가로 충분
권장 옵션: 옵션 A (replace). 수동 메모가 없거나 canonical 생성이 항상 우선이라면 replace가 더 단순하고 소비자 측 추가 로직이 불필요하다. 수동 메모가 중요하면 옵션 B로 전환.
