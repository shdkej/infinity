완료·감사 report의 후속 intent capture 계약 반영

01 · 무엇이 문제였나

완료·감사 report의 실행 가능한 후속 조치가 사용자 재지시를 기다리며 Inbox 등록 계약과 report 가시성에서 누락될 수 있었다.

02 · 어떻게 해결하나

자동 등록 조건, 승인 대기 경계, 중복 방지, 필수 필드, report 필드와 lane 재검증을 canonical 운영 문서에 반영했다.

핵심 내용 · 리서치 본문
  1. 자동 등록은 정리·검증·문서/인덱스 보강·로컬 hygiene처럼 승인·외부 공개·파괴·자격증명·권한·비용이 없는 범위로 제한했다.
  2. 구현·배포·외부 발송 등은 Inbox에 등록하되 user-approval gate를 기록하고 실행을 보류한다.
  3. 근거 신호·기대 산출물·완료 기준이 없거나 동일 목적 intent가 있으면 등록하지 않고 이유/기존 id를 report에 남긴다.
  4. 새 intent의 target은 genie로 정규화하며 projects/task_type/topics/priority/permission/goal/success_criteria/next_action을 요구한다.
  5. heartbeat는 등록 후 INTENTS.md를 재독해 Inbox 제거와 lane 존재를 확인한다.

근거: agent-wiki Meta/AGENTS 문서, INFINITY_OPERATING_RULES.md, heartbeat.md, ARTIFACT_RULES.md, EVALUATION_INDEX.md.

다음 판단: Red PASS와 원격 push 확인 뒤 ops-25를 Archive한다.

역할 판단과 종합

Planner: 범위·완료 기준을 확정. Developer: 운영 규칙과 heartbeat 계약에 최소 변경을 적용. Marketer: 외부 카피 작업은 해당 없음, 등록 자체는 침묵. Operator: 승인/외부/비용 경계를 차단하고 dirty worktree를 보존. 지니는 새 daemon·기존 intent 재활성화·report 링크만 남기는 안을 기각했다.
