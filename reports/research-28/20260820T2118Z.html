autoresearch를 Infinity에 접목하는 최소 운영 모델

무제한 자율 실행을 옮기지 않고, 고정 기준·좁은 변경·bounded 반복·기록·rollback만 기존 Intent·Heartbeat·Red 게이트 안에 삽입한다.

axis ax1 · 01 · WHAT WAS STUDIED
Karpathy autoresearch의 고정 evaluator, 단일 변경면, 고정 실행 예산, keep/discard/crash, 결과 원장을 Infinity의 Intent·Artifact·Report·Red와 대조했다.
axis ax2 · 02 · RECOMMENDATION
조건부 진행 가능. 문서·프롬프트 평가부터 최대 3회 sandbox 실험으로 검증하고, 자동 배포·cron·secret·외부 네트워크·유료 실행은 별도 승인 전까지 금지한다.
핵심 결과
  1. 최소 단위는 bounded experiment Intent, append-only Artifact, baseline 대비 HTML Report다.
  2. 필수 경계는 fixed evaluator, metric, change scope, stop conditions, rollback_ref, lock/budget이다.
  3. 사용자-facing 명칭은 “반복 개선 루프”; autoresearch는 내부 참고명으로만 둔다.
  4. 1~2주 동안 고정 fixture로 재현성·판정·롤백·비용·중단 조건을 검증한다.
Planner

전면 자동화 대신 단일 Intent·지표·변경 축으로 축소한다. 세션 예산과 종료 조건을 먼저 고정한다.

Developer

Intent·Artifact·HTML Report 3층 구조와 baseline/metric/rollback 필드를 제안한다. 실제 스키마·코드 수정은 후속 Intent로 분리한다.

Marketer

사용자-facing 명칭은 “반복 개선 루프”로 하고, 작은 변경·같은 기준·되돌리기 중심으로 설명한다.

Operator

sandbox·전용 branch·비용 상한·수동 승인 게이트를 필수로 둔다. 자동 production 반영·권한/secret/외부 공개 변경은 기각한다.

역할 종합

네 역할의 합의는 고정 기준·좁은 변경·관측·rollback이다. 최종 순서는 설계 검토 → 승인된 sandbox dry-run → Red pass → 별도 구현/운영 Intent다.
