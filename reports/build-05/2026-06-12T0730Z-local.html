Control Center Editable CMS — 설계 (첫 안전 액션)

build-05 · 2026-06-12T07:30Z · doc-only design · 승인 전 단계

axis ax1 · 판단

사용자 피드백 "CMS는 수정이 핵심"에 따라 build-04 read-only Control Center를 실제 수정 진입점으로 확장해야 한다. 다만 첫 안전 액션은 코드 실행이 아니라 editable surface 스키마 + field-level draft edit/diff preview 설계다. write API / auth / production deploy / token 서버 기능 / Terraform·AWS 리소스는 본 단계에서 설계 경계 텍스트로만 다루고 구현하지 않는다.

axis ax2 · 결과

설계 산출물 artifacts/build-05/control-center-editable-cms-design.md를 작성했다. editableSurfaces 스키마, Family Wedding 안내장 3필드(NOTICE / 본문 도입 / OG description) 첫 인스턴스, anchor 기반 unified diff preview 흐름(preview.write: "none"), change-log 모델, intent 성공 기준 매핑을 담았다. 정본 파일은 변경하지 않으며 publish/deploy는 전부 approval-needed 자리로만 남겼다.

이번 단계에서 한 것
  • editableSurfaces 선언적 스키마 형상 정의 (id/필드/anchor/검증/preview/publish/changeLog)
  • 첫 editable target으로 Family Wedding 안내장 3필드 인스턴스 설계
  • 입력 → 위치결정(anchor) → 검증 → unified diff preview → 커밋 초안 흐름 정의 (정본 미변경)
  • commit SHA / deploy run / public URL 검증을 잇는 change-log 모델
  • build-05 성공 기준 5개를 설계로 매핑
닫아둔 범위 (승인 경계)
  • write API — 정본 파일 직접 쓰기 미구현, placeholder만
  • auth / permission, 다중 사용자 roles — 미설계
  • production deploy button, GitHub/AWS token 서버 function — approval-needed 자리로만
  • Terraform / AWS resource 추가 0, 비용·destructive·force-push·외부 발송 없음
  • 비밀값(secret) 편집은 editable field에서 원천 제외
다음 단계 후보 (별도 승인/단계)
  • Control Center UI에 editableSurfaces 읽기 전용 바인딩 + diff preview 렌더
  • 정본 미변경 unified diff 생성기 소규모 구현 (write API 아님)
  • Family Wedding NOTICE 1필드 수동 수정 루프 2–3회로 change-log 모델 검증
  • 안정화 후 deploy 버튼/token 서버 기능은 승인형 별도 intent로 분리
