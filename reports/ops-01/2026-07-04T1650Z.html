weekly autopush를 프롬프트에서 결정적 스크립트로 이관

self-healer가 같은 git 실패에 프롬프트 패치를 5겹까지 덧대던 부패 루프를, LLM 판단이 필요 없는 배시 스크립트 하나로 끝냈다.

01 무엇이 문제였나
weekly-main-workspace-autopush 크론이 git sync를 LLM 프롬프트로 수행해, 실패할 때마다 self-healer가 예외 문구를 덧대며 동일 규칙이 5겹 누적됐다 (CRON_REDESIGN_2026-07-04.md 진단 5).
02 어떻게 해결했나
system/scripts/weekly_workspace_sync.sh를 만들어 안전 staging → commit → rebase pull → non-force push를 결정적으로 수행하고, 크론 payload를 command 실행으로 교체했다. 프롬프트가 사라졌으니 패치가 쌓일 표면 자체가 없다.
핵심 내용 · 리서치 본문
핵심 발견
  1. 실측 테스트: 스크립트 직접 실행으로 19개 파일 커밋(453f22d) + push 성공, exit 0.
  2. 크론 하네스 수동 run도 ok (2.3초). agentTurn 대비 실행 시간과 토큰이 사실상 0이 됐다.
  3. 기존 프롬프트의 안전 규칙(ignored 경로 pathspec 제외, diff exit 1 = 변경 있음, no force-push)은 스크립트 로직으로 그대로 옮겼다.
LLM 판단이 필요 없는 반복 작업은 프롬프트 패치로 고치지 말고 결정적 스크립트로 이관한다 — self-healer의 수리 대상에서 빼는 것이 근본 수리다.
