Virtue 잡별 온보딩 체크리스트 감사표

행동 중심 온보딩 체크리스트(Appcues/Supademo/ProductLed)를 Virtue 잡별 first value 경로에 맞춰 적격/범퍼/맥락 폴백/금지 4분류로 감사한 실행 로그.

01 무엇이 문제였나
first value가 잡별로 다른데(J1/J2/J4=deed_saved, J3=deed_judged) 단일 체크리스트를 붙이면 J3의 정상 종료(저장 없이 판정에서 닫힘)를 "저장 미완료"로 오독하고, 기능 안내 목록이 first value 경로를 가린다.
02 어떻게 해결하나
잡별 체크리스트 감사표를 추가해 각 행동을 적격(CL-ELIGIBLE)·범퍼·맥락 폴백·금지 4분류로 가르고, 체크리스트를 잡의 first value에서 끊었다 — J1/J2/J4는 저장까지, J3는 판정에서 종료(저장은 금지 항목). 폴백은 막힘 4분류 중 B-LOST에만 발동.

  • 계승한 기준: first value 매핑(J1/J2/J4=deed_saved, J3=deed_judged) 재정의 0 · deed_save_capped=availability/friction · synthetic/mock/self-test·소수 표본 비결정 등급 · J3 저장 없는 종료=정상(B-NORMAL) · 본체/범퍼 + 막힘 4분류(Product Body vs Bumper By Job, m31).
  • 이번에 새로 배운 것: 체크리스트는 first value 위치를 따라 잡별로 길이·종료점이 다르다 — J1/J2/J4는 입력→판정→저장 3단계, J3는 입력→판정 2단계에서 끝난다. 같은 "저장하기"가 J1엔 적격, J3엔 금지로 부호가 뒤집힌다. 맥락 폴백(conversational bumper)은 막힘 4분류 중 B-LOST에만 발동한다.
  • 다음 Marketer에게 넘길 규칙: 체크리스트를 감사할 때 먼저 잡의 first value 이벤트(저장이냐 판정이냐)를 확인하고 거기서 체크리스트를 끊는다. J3에 저장을 필수 체크로 넣지 않는다. 안내는 B-LOST에만 띄우고, 가용성·정상 종료·제품 불일치엔 띄우지 않는다. 체크리스트 완료율을 활성화 합격선으로 쓰지 않는다.
