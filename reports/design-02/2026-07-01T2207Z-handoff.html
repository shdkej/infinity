카드뉴스 첫페이지 후킹 개선 실험 로컬 실행 핸드오프

스케줄 윈도우는 열렸지만, 이번 사이클은 Intent triage 범위를 넘는 원본 카드뉴스 탐색을 시작하지 않고 다음 실행자가 바로 검토할 입력과 판정축만 고정한다.

01 무엇을 조사/정리했나
Active design-02의 실행 조건과 성공 기준을 다시 확인하고, 다음 로컬 실행자가 처음 열어야 할 최근 카드뉴스 첫 페이지 묶음과 비교 기준을 손실 없이 넘길 수 있는 최소 핸드오프 범위를 정리했다.
02 핵심 결과
이번 heartbeat는 구현·재생성 없이 정확한 다음 스코프를 남기는 것으로 종료한다. 다음 실행은 최근 카드뉴스 첫 페이지 3~5개만 열어 훅 판독, 가설 3개, 개선안 3개, 필요 시 preview 1개까지 한 번에 닫는 것을 검증 게이트로 삼는다.
핵심 내용 · 리서치 본문
핵심 발견
  1. 현재 원장만으로는 실제 비교 대상인 "최근 카드뉴스 3~5세트"의 파일 경로나 preview 산출 위치가 지정돼 있지 않아, 이 사이클에서 무작정 탐색을 시작하면 bounded triage를 넘기 쉽다.
  2. success criteria는 실험 결과 요약, 이긴 hook 원칙, 즉시 적용할 개선안 3개, HTML report다. 따라서 다음 실행은 자료 수집보다 판독과 요약을 한 번에 끝내는 좁은 범위가 더 적합하다.
  3. 제약상 공개 배포, 기존 카드뉴스 교체, 대량 재생성, 외부 비용, 임의 생성 이미지 대체는 금지되므로 첫 실행은 로컬 파일 판독과 필요 시 preview 1개 생성까지만 허용된다.
다음 실행자는 최근 카드뉴스 첫 페이지 후보를 찾는 즉시 범위를 3~5개로 고정하고, 판독 메모와 hook 비교를 같은 report 안에서 닫아야 한다. 새 intent 분기나 대량 탐색으로 확장하지 않는다.
근거 · 소스

INTENTS.md Active 항목과 intents/active/design-02.md의 목표, schedule window, success criteria, 금지사항만 확인했다.

다음 판단

다음 로컬 실행에서 최근 카드뉴스 저장 위치가 즉시 확인되면 실험을 완료 보고까지 진행하고, 위치가 불명확하면 경로 후보와 필요한 확인 질문만 남긴 Waiting 또는 handoff로 닫는다.

다음 로컬 실행 범위
열 파일 / 확인 대상
  • 최근 카드뉴스 output 또는 preview가 모이는 디렉터리 1곳만 특정한다.
  • 그 안에서 첫 페이지 비교에 충분한 3~5세트만 고른다.
  • design-01 실행 규칙 문서가 바로 옆에 있으면 keyword-title과 모바일 안전영역 기준만 재사용한다.
검증 게이트
  • 각 샘플마다 "왜 멈추지 않는지 / 왜 읽히는지" 한 줄 판독이 있어야 한다.
  • hook 가설 3개 이상이 제목, 이미지 구도, 첫 문장 조합 축으로 분리돼야 한다.
  • 개선안 3개는 가독성, 호기심, 주제 명료성, 브랜드 결, 모바일 안전영역 기준으로 비교돼야 한다.
  • 최종 HTML report는 reports/design-02/{timestamp}.html에 남기고, 필요 시 preview 1개만 추가한다.
금지사항
  • 공개 라이브러리 배포, 기존 카드뉴스 교체, 대량 재생성 금지
  • 외부 비용 발생 작업, 외부 계정 연결, 임의 생성 이미지 대체 금지
  • 비교 대상 탐색을 repo-wide audit로 키우지 말 것
