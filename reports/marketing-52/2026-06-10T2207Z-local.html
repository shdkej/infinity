Virtue `/add` 첫 입력 prompt design 감사표

AI 온보딩의 click tax 렌즈를 Virtue prelaunch에 맞춰, 첫 입력 전 문구가 UI 설명인지, 판정 위임인지, 원하는 결과를 AI에게 알려주는지 분리했다.

01 무엇이 문제였나
Virtue `/add`는 튜토리얼 click tax는 낮지만, 첫 입력 문구가 원하는 결과를 AI에게 알려주기까지는 아직 명확히 돕지 않는다. 특히 `AI 채점`·`보수적으로 채점`은 J3 호기심을 부르면서도 판정 위임으로 읽힐 수 있다.
02 어떻게 해결하나
UI instruction / judgment delegation / desired-result teaching 3분류 감사표를 만들고, J1-J4별 proposal-only 후보와 approval-needed 경계를 고정했다. 신규 계측·공개 카피·코드·배포 변경은 0이다.

계승한 기준
  • First Value Mapping: J1/J2/J4는 저장, J3는 판정 결과에서 첫 가치가 닫힌다.
  • Guided First-Value Is A Four-Stage Handoff: 이번 작업은 첫 입력 전 단계만 확대한 것이다.
  • Decision-Delegation Risk Rides The Verb: `채점`/`판정` 동사는 판결 프레임 위험이 있다.
이번에 새로 배운 것
  • click tax reduction은 원하는 결과와 무관한 탐색·튜토리얼 제거이지, 성찰을 만드는 입력 시간 제거가 아니다.
  • 첫 입력 prompt design은 UI instruction, judgment delegation, desired-result teaching으로 나눠야 안전하다.
  • Virtue의 현재 gap은 "무엇을 했나" 질문은 있으나 "어떤 결과를 AI에게 원하나"를 잡별로 지정하게 돕지는 않는다는 점이다.
다음 Marketer에게 넘길 규칙
  • `/add` prompt 후보는 먼저 UI 설명인지, 판정 위임인지, 원하는 결과 가르치기인지 표시한다.
  • 전역 예시/placeholder 최적화는 금지한다. 잡별 관찰 없이 한 예시를 넣으면 다른 잡을 방해할 수 있다.
  • J3에는 저장을 정상 후속 행동으로 강제하지 않는다. 공개 카피·버튼·placeholder 변경은 approval-needed다.
MARKETING_LEARNINGS.md 승격 후보

Prompt Design Teaches Desired Result, Not UI Or Judgment를 승격했다. 핵심은 AI 첫 입력 문구를 UI instruction / judgment delegation / desired-result teaching으로 분리하고, click tax reduction이 성찰 입력 자체를 제거하지 않게 하는 것이다.
