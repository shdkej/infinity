NO_REPLY 실행 시 4.7万~6.7万 토큰을 소비하는 패턴을 읽기 예산 제한과 조기 종료 조건으로 차단한다.

01 🟡 무엇을 점검했나
OpenClaw evaluator가 NO_REPLY 정상 종료임에도 4.7万~6.7万 tokens을 반복 소비 — 4시간 간격 감시 크론의 비용 대비 신호 효율이 낮은 상태
02 ✅ 이상 여부·조치

핵심 내용 · 문제 분석
핵심 발견
  1. 토큰 낭비 패턴 확인 — sam-proposer가 최근 24시간 evaluator 실행 데이터에서 4.7万~6.7万 tokens/run을 측정. NO_REPLY 결론에도 전체 컨텍스트를 로드하는 구조적 원인.
  2. 원인: 읽기 예산 미설정 — 현재 evaluator는 EVALUATION_NOTES.md 전체, OPERATING_LESSONS.md 전체, 크론 로그 전체를 로드한 후에 NO_REPLY를 판단함. 결론이 초기에 확정되어도 읽기를 멈추지 않는다.
  3. 해결 지점: 3가지 읽기 제한 — (a) EVALUATION_NOTES.md는 tail -n 120만, (b) OPERATING_LESSONS.md는 관련 섹션 헤더로 필터, (c) 크론 실행 로그는 최근 24시간 요약만 허용.
  4. 추가 조치: 조기 종료 게이트 — 초기 스캔에서 미해결 이슈 없음이 확정되면 추가 읽기 없이 바로 NO_REPLY 반환. 재현 1개 확인 시 즉시 종료.
  5. 검증 기준 — 변경 후 다음 2회 실행에서 total_tokens가 이전 4.7万~6.7万 범위보다 의미 있게 낮아지면 성공.
