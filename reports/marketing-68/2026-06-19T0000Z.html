Virtue Agent-Readable Surface Audit

4개 공개 표면의 오독 경계 확립 — agent may read / must not infer / human handoff wording / launch-after reuse 기준표

01 무엇이 문제였나
Virtue의 agent-readable 표면(Landing · README · llms.txt · In-app 카피)에서 AI 판결 프레임 언어가 에이전트에게 그대로 노출될 경우의 오독 경계가 내부적으로 미정의 상태였다
02 어떻게 해결하나
4개 표면 × 5축(current evidence / agent may read / agent must not infer / human handoff wording / launch-after reuse) 감사표 완성. 공통 경계 1세트 확립, human handoff wording 후보 4개, zero-change 확인
핵심 내용 · 감사 결과
핵심 발견
  1. 오독 위험은 언어 레이어에만 존재 — Virtue는 외부 자율 행동이 구조적으로 없으므로(m38), 에이전트가 읽어도 "AI가 대신 행동하는 경로"는 없다. 오독 위험은 오직 "AI가 대신 결정한다"는 판결 프레임 언어에서만 생긴다.
  2. In-app 카피의 판결/관점 프레임 불일치가 주된 소재 — "AI 채점"(판결 프레임) vs "AI가 본 오늘"(관점 프레임) 혼재(m45). 에이전트 크롤 시 판결 프레임이 그대로 노출된다.
  3. 공통 경계 1세트가 전 표면에 동일 적용 가능 — Virtue의 구조적 보호(사람 마지막 선택, 외부 자율 행동 없음)가 전 표면 공통 경계를 보장한다. 표면별 차이는 "현재 content 확인 가능 여부"와 "launch-after 재사용 경로"뿐이다.
  4. llms.txt만 미배포 상태 — 나머지 3개 표면은 현재 content 기반 감사 가능. llms.txt는 이 표 공통 경계로 초안 작성 가능, 실제 배포는 approval-needed.
  5. human handoff wording 후보 4개 확보 — 내부 기준으로만 사용. 공개 반영은 approval-needed. 관점 프레임(m45) 일관 적용을 위한 후보 완비.
즉시 실행 가능한 다음 단계: llms.txt 초안을 Inbox에 등록(L1 docs-only). In-app 카피 프레임 정렬은 m45 proposal-only 유지. 공개 표면 변경(robots/llms 배포, public copy, deploy)은 모두 approval-needed.
