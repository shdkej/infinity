Virtue AI Authorization Boundary Table

WEF/Capgemini ACAP 관점을 Virtue prelaunch 신뢰 경계로 번역 — J1-J4별 권한 경계 내부 문서 고정.

01 무엇이 문제였나
J1-J4별 AI 권한 경계가 내부 기준 문서로 고정되지 않음 — 첫 사용자가 AI 판정을 도덕적 단정·사실·결론으로 과신할 경계선이 불명확한 상태.

핵심 내용 · 권한 경계 근거
핵심 발견
  1. user_delegates 범위가 잡별로 다르다 — J1은 해석 보조, J3는 관점 확인(저장 없음), J4는 영구 저장 보조. 같은 AI 판정 카드가 잡마다 다른 위임 범위를 가진다.
  2. virtue_must_not_do의 공통 핵심은 3개 선행 기준으로 수렴한다 — "판결 프레임 금지(marketing-45)", "자율 외부 행동 없음(marketing-38)", "에이전트 오독 경계(marketing-66)"가 단일 금지선이 된다.
  3. J3 human_decision_required는 특수 케이스 — 무저장 종료가 오류가 아닌 정상 완료이므로, "저장/건너뛰기"는 강요가 아닌 선택으로 명시. 다른 잡과 달리 J3는 저장 없이 first value 완료.
  4. evidence_to_show는 신뢰 증거를 실행 경계로 번역한 첫 컬럼 — marketing-65의 신뢰 증거 인벤토리를 "사용자에게 보여줄 수 있는 경계"로 구체화. 기존 인벤토리를 재정의하지 않고 계승.
  5. ACAP "무엇을 허용할 것인가"는 Virtue에서 "판정 프레임 허용 방식"으로 수렴한다 — Virtue에는 외부 자율 행동이 없어, 신뢰 경계 문제는 "무엇을 실행하나"가 아니라 "AI 판정을 어떤 언어로 제시하나"에 있다.
추천: 이 표를 onboarding·FAQ·public explainer·llms.txt 작성 시 J1-J4별 신뢰 경계 참조 표준으로 사용할 것. approval 없이 공개 발행 금지. first-10 관찰에서 "AI에게 무엇을 맡긴다고 느꼈는가" 질문 설계 시 user_delegates 컬럼을 잡별 기대 기준으로 사용.

J1-J4 권한 경계표

5컬럼 전체 내용. 모바일에서는 카드로 렌더됩니다.

Job user_delegates virtue_may_do virtue_must_not_do human_decision_required evidence_to_show
J1 — 행동 기록 저장 기록한 행동의 AI 관점 해석 보조 deed_judged 카드 제공, 저장 선택 안내, 판정 근거 문장 표시 저장 강요, 도덕적 단정, 기록 외부 전송, 자동 저장 저장 여부 — 저장 = 명시적 수용(선택) 저장 전 취소·재시도 가능, 외부 전송 없음, 판정 = 관점(결론 아님)
J2 — 누적 레벨 패턴 반복 기록 기반 패턴·레벨 해석 보조 누적 저장 집계, 레벨 패턴 피드백 제공, 누적 기준 공개 단기 표본으로 성격·능력 결론, 자동 행동 지시, 누적 데이터 외부 공유 계속 기록할지 여부 — 반복 저장은 선택 레벨·누적 맥락 공개, "표본 적을 때 패턴 미확정" 명시
J3 — AI 판정 보기 특정 행동의 AI 관점 확인 (저장은 선택) deed_judged 카드 제공, 판단 한계 표시, 재판정 안내 무저장 종료를 이탈·실패로 처리, 판정 결과 외부 공유, 판정을 사실·결론으로 제시 저장/건너뛰기 — J3 무저장 종료 = 정상 완료 "판정 = 관점, 결론 아님" 명시, 판단 한계 문장, 무저장 종료 비용 0
J4 — 영구 주석 선택한 기억에 AI 주석 영구 저장 보조 deed_judged + 영구 저장 제공, 수정·삭제 옵션 안내 자동 공유·외부 전송, 민감 정보 자동 저장, 타인 관련 자동 주석 공유·삭제·보관 여부 — 영구 저장 전 명시 선택 수정·삭제 가능성 표시, privacy boundary 명시, 저장 전 선택 affordance
공통 구조적 경계: 어떤 잡에서도 자율 외부 행동 없음 · 마지막 선택권은 사용자 · 판정 = 관점(결론 아님) · 에이전트 오독 경계(marketing-66) 유지.
