Virtue 홈 gating 재실행용 정확한 체크아웃과 분기 지점 캡처

이번 사이클은 구현을 넓히지 않고, 다음 로컬 Claude 실행이 바로 들어갈 수 있도록 실제 소스 파일과 검증 포인트를 한 장으로 고정했다.

01 무엇이 문제였나
기존 Waiting 상태는 /home/ubuntu/dev/virtue-rebirth-app 이 실제 앱 체크아웃인지, 그리고 홈 gating 계약을 어디서 검증해야 하는지가 아직 실행 패킷 수준으로 고정되지 않았다는 점이었다.
02 어떻게 해결하나
실제 홈 소스는 apps/web/src/app/page.tsx 로 확인됐고, gating 분기는 이미 stats.count === 0, stats.count > 0 && recent.length === 0, recent.length === 0 조합으로 존재한다. 다음 실행은 이 파일만 열어 구현/검증을 마치면 된다.
핵심 내용 · 리서치 본문
핵심 발견
  1. 후보 체크아웃 /home/ubuntu/dev/virtue-rebirth-app 안에 실제 홈 파일 apps/web/src/app/page.tsx 가 존재한다.
  2. 파일 상단에서 const isFirstVisit = stats.count === 0; 와 const isReturningWithoutRecent = stats.count > 0 && recent.length === 0; 가 이미 선언돼 있어 gating 계약을 다시 설계할 필요가 없다.
  3. 최근 덕행 empty-state 는 recent.length === 0 분기와 isReturningWithoutRecent title/description 분리로 연결돼 있어, 다음 실행의 검증 범위를 홈 한 파일과 타입체크로 제한할 수 있다.
다음 로컬 실행은 copy polish, 리디자인, 배포 작업 없이 apps/web/src/app/page.tsx 의 홈 gate 정합성 검증과 필요한 최소 수정, 그리고 scoped verification 만 수행한다.
근거 · 소스

rg --files 로 홈 파일 존재를 확인했고, rg -n "stats.count|recent.length|retained|recent" 및 해당 코드 스니펫 검토로 분기 위치를 캡처했다.

다음 판단

다음 실행에서 retained proof surface 가 같은 파일 또는 인접 컴포넌트에 있는지 캡처한 뒤, first-visit 카피가 재노출되지 않음을 확인하면 완료/재활성화 판단이 가능하다.
