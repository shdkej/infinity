Virtue 잡별 Activation 후보 묶음 레지스트리

J1-J4별 first value·후보 묶음·관찰 window·판독 가능 항목·수기 관찰·금지 해석을 1장으로 고정한 docs-only 레지스트리

01 무엇이 문제였나
Virtue prelaunch에서 J1-J4 잡별 activation 신호 기준이 단일화되어 있어, 소수 표본을 단일 rate로 오독하거나 잡별 first value 차이를 놓칠 위험이 있다
02 어떻게 해결하나
J1-J4별 first value 이벤트·후보 묶음·관찰 window·금지 해석을 1장 레지스트리로 고정했다. 이벤트 판독 가능 항목과 수기 관찰 항목을 분리해 prelaunch 저신호 관찰 정밀도를 높였다.
핵심 내용 · 레지스트리 요약
핵심 발견
  1. J1/J2/J4는 deed_saved, J3는 deed_judged가 first value — 잡마다 activation 완료 이벤트가 달라 단일 activation rate 판정은 잡별 오독을 유발한다
  2. 이벤트 판독 가능 항목(on-instrument)과 수기 관찰 항목(off-instrument)을 분리하면 prelaunch 저신호 환경에서 instrument 이외 신호를 체계적으로 수집할 수 있다
  3. J3의 deed_judged 후 무저장 종료는 실패가 아니라 정상 종료 — 레지스트리에 명시해 judged-saved 갭 오독 경로를 차단했다
  4. 표본 부족 시 금지 해석 목록(단일 이벤트·비율 산출·외부 벤치마크)을 잡별로 명시하면 prelaunch 관찰 오독 경로가 구조적으로 줄어든다
  5. marketing-79~100 archive 핵심 계열 검토 결과 충돌 없음 확인; source_signal 로컬 파일(후속 실험 후보 1번 연결)만 로컬 검증 미완
레지스트리는 "측정 가능 상태" 고정이지 성패 판정이 아니다 (m34). 각 잡의 게이트는 first value 이벤트 발화 여부만 보고, 비율·TTV·D7%는 이 단계 밖이다. 출시 후 실제 값 해석은 Correlation Readiness gate(m37)를 거친 뒤에만 한다.
