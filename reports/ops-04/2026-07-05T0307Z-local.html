OpenClaw evaluator 경고성 탐색 템플릿 축소

Active execute_local intent의 대상 정본을 확인하고, 이미 반영된 제한 규칙을 근거로 Infinity 원장을 완료 처리했다.

01 무엇이 문제였나
OpenClaw evaluator가 반복 NO_REPLY 실행 중 `~` 경로 search, agent-scoped search, `git ls-files`, `2>/dev/null` literal target 같은 경고성 탐색을 남기던 문제가 Active intent로 남아 있었다.
02 어떻게 해결하나
현재 evaluator 정본은 `git status --short` + 절대경로 파일 읽기를 기본으로 삼고, no-match를 실패로 보지 않으며, agent-scoped 전역 search와 리다이렉션 문자열 target 사용을 금지한다.
핵심 내용 · 리서치 본문
핵심 확인
  1. `/home/ubuntu/.openclaw/workspace/system/evaluators/openclaw-evaluator.md`의 반드시 확인할 대상은 `git status --short`, 최근 변경 파일 최대 3개, 필요한 자동화 흔적으로 제한되어 있다.
  2. 실행 제한은 `~` 축약 대신 절대경로를 우선 사용하고, agent-scoped 전역 search를 기본 단계에서 쓰지 않으며, no-match 허용을 명령 레벨에서 처리하도록 명시한다.
  3. scoped git status 기준 OpenClaw evaluator 정본과 EVALUATION_NOTES에는 미커밋 변경이 없어, 이번 사이클에서는 Infinity intent 원장과 HTML report만 기록했다.
다음 정기 evaluator diagnostics에서 search target/path warning이 다시 발생하면 새 구현 intent가 아니라 재발 감시 항목으로 좁게 분리한다.
상세 · 검증

대상 파일에서 남아 있는 `~/.openclaw`, `git ls-files`, `2>/dev/null` 문자열은 과거 EVALUATION_NOTES의 근거 기록 또는 금지 규칙 설명이며, 실행 템플릿으로 호출되는 지시는 아니었다. 정본 절차에는 경고 패턴 4종의 반대 규칙이 직접 들어 있다.
