아프지마 앱 병원 API 호출 흐름 검증

build-13 · 2026-06-24T00:50Z · repo: shdkej/afzma · permission: L1 read-only verification

axis ax1 — 무엇을 확인했나

로컬에 shdkej/afzma를 체크아웃한 뒤, 병원 추천 데이터가 UI 입력에서 API route, backend service, HIRA 공공 API 호출, 응답 매핑, UI 병원 목록 표시까지 이어지는지 read-only로 추적했다. 운영 HIRA 호출은 HIRA_API_KEY와 외부 공공 API를 건드릴 수 있어 실제 네트워크 호출은 하지 않았다.

axis ax2 — 결론

코드상 호출 흐름은 연결되어 있다. 홈 입력은 위치값과 함께 /response/[id]로 이동하고, 응답 화면 hook이 /api/chat 또는 /api/history/[id]를 호출한다. 서버는 MedicalService.processSymptom() 또는 getChatDetail()에서 getRecommendedHospitals()를 호출한다. 다만 실제 HIRA 호출 성공은 HIRA_API_KEY가 있어야 하며, 키가 없거나 API 오류/빈 응답이면 mock 병원 데이터로 폴백한다.

호출 흐름

단계파일확인 내용
위치 수집hooks/useLocation.ts브라우저 geolocation으로 lat/lon을 상태에 저장한다. 실패 시 에러만 저장하며 앱 흐름은 계속된다.
홈 입력app/page.tsx사용자 증상을 /response/{uuid}?message=...로 넘기고, 위치가 있으면 lat/lon query를 추가한다.
클라이언트 APIlib/medical-api.tsfetchMedicalAnalysis()가 POST /api/chat에 message/chatId/lat/lon을 보낸다. 히스토리는 GET /api/history/[id]?lat=&lon=로 조회한다.
응답 화면hooks/useMedicalResponse.tsquery의 message가 있으면 새 분석, 없으면 히스토리 조회. 결과의 analysis/hospitals를 상태에 저장한다.
Route handlerapp/api/chat/route.ts, app/api/history/[id]/route.tsNext route가 controller로 요청을 전달한다.
Controllerbackend/controller.tsmessage 누락은 400, 내부 오류는 500. 정상 시 service 결과를 JSON으로 반환한다.
Servicebackend/service.tsAI 분석 후 getRecommendedHospitals(analysis.department, lat, lon)를 호출한다. 히스토리 조회에서도 저장된 분석을 다시 읽어 병원을 재추천한다.
외부 병원 APIbackend/service.tshttps://apis.data.go.kr/B551182/hospInfoServicev2/getHospBasisList에 serviceKey, dgsbjtCd, 선택적 xPos/yPos/radius를 붙여 호출한다.
UI 표시components/response/HospitalBottomSheet.tsx, HospitalDetailModal.tsx병원 목록/상세 정보를 표시하며 빈 배열이면 “주변에 해당 진료과 병원을 찾을 수 없습니다.”를 보여준다.

실제 호출 상태

항목판정
UI → 서버 연결연결됨
서버 → HIRA API 연결코드상 연결됨
실제 HIRA 네트워크 호출미실행 — API 키/외부 호출 경계 때문에 read-only 검증에서 차단
키 없을 때 동작HIRA_API_KEY 없으면 mock 병원 반환

Claude Code 실행차단 — 로컬 claude는 존재하지만 401 인증 오류로 실행 실패. SAM이 동일 로컬 체크아웃에서 read-only 검사 수행.

리스크와 수정 후보

  • 실제 API 실패와 mock fallback이 UI에서 구분되지 않는다. 운영에서는 “실제 병원 추천”처럼 보일 수 있다.
  • getRecommendedHospitals()는 fetch() 후 HTTP status를 따로 확인하지 않고 XML 파싱으로 넘어간다.
  • 공공 API serviceKey를 URL에 직접 붙인다. 로그에서는 키를 숨기지만, query 생성 방식과 encoding은 실제 키 형태로 한 번 검증해야 한다.
  • 위치 권한 실패 시 위치 없는 전국/진료과 검색으로 넘어가며, 사용자에게 위치 기반 추천 실패 상태가 명확히 노출되지 않는다.
  • 실제 호출 검증은 HIRA_API_KEY가 있는 안전한 로컬 환경에서 1회 read-only 요청으로 별도 승인 후 진행하는 편이 맞다.
