Virtue agent-led growth fit / no-fit 경계표

"AI 제품이면 agent-first 유통부터"라는 오독을 막기 위해, Virtue prelaunch에 agent-led growth가 맞는 조건과 맞지 않는 조건을 한 장으로 가른 docs-only 경계표. 공개 카피·robots/sitemap/llms.txt·API/MCP·코드 변경 0.

01 🔴 무엇이 문제였나
AI 제품 유통 논의가 agent-led growth(에이전트가 API·문서를 발견하고 task completion으로 활성화)로 기울면서, "AI 제품이니까 agent-first 유통·MCP·API·agent docs부터"라는 범주 오류가 생긴다. Virtue는 아직 첫 10명 학습도 안 끝난 prelaunch이고, 가치 본체가 사람의 성찰·기록·자기 선택이라 이 논의를 그대로 복사하면 무거운 표면을 먼저 만들고 제품 의미를 흐릴 위험이 있다.
02 ✅ 어떻게 해결하나
유통 모드를 가르는 기준을 "AI 제품인가"가 아니라 "가치를 누가 완료하나(task completion subject)"로 다시 세우고, 8개 판단 차원의 fit / no-fit / Virtue 현재 위치를 한 표로 고정했다. Virtue가 "사람이 경험·선택" 칸에 있는 한 agent-readable은 설명(read-about)까지만 후보, 실행(do-for-you: MCP/API/agent onboarding)은 no-fit이다.
  1. 8개 차원 전부에서 Virtue는 현재 no-fit 또는 보존 대상 — 안 만드는 이유는 게으름이 아니라 제품 의미·구조적 안전장치 보존(§3).
  2. agent-readable 표면을 read-about(설명) vs do-for-you(실행)로 갈라, 공개 read-about는 approval 후보·do-for-you는 no-fit으로 분리(§4).
  3. 나중에 다시 열 launch/post-launch gate G1~G4(설명→export→연결→실행 표면 순)를 실사용 신호 기준으로 사전 정의(§5).
  4. 금지선·first value 매핑 재정의 0, event anchor drift 0, code diff 0, conflict marker 0(§6).

이번에 새로 배운 것

  • 유통 모드 선택은 "AI 제품인가"가 아니라 "가치를 누가 완료하나(task completion subject)"로 갈린다.
  • 에이전트 task completion이 곧 가치인 제품(API/B2B/워크플로 편입형)엔 agent-led growth가 맞지만, 사람의 경험·선택이 본체인 Virtue엔 do-for-you 유통이 제품 의미를 소거한다(성찰을 대행하면 성찰이 사라진다).
  • 그래서 Virtue에서 agent-readable은 read-about(설명)까지만 후보, do-for-you(실행: MCP/API/onboarding)는 no-fit. m38(자율 행동 없음)·m45(사람 마지막 선택)를 신뢰/카피 층에서 유통 전략 층으로 확장한 것.
  • 8개 판단 차원 전부에서 Virtue는 no-fit 또는 보존 대상 — agent path를 열면 "외부 자율 행동 없음"과 "사람 마지막 선택" 두 안전장치가 동시에 무너진다.

다음 Marketer에게 넘길 규칙

  • agent-led growth/AI 유통 논의가 들어오면: ① "가치를 누가 완료하나"를 먼저 묻는다(에이전트 task vs 사람 경험·선택) → ② agent-readable 후보는 read-about인가 do-for-you인가로 가른다 → ③ Virtue가 "사람 경험·선택" 칸이면 do-for-you는 no-fit, 공개 read-about는 approval 후보 → ④ 재검토는 §5 게이트(실사용 신호) 로만 연다.
  • read-about 표면도 "사람 대신 에이전트가 Virtue를 쓴다"로 읽히지 않게 m45 동사 프레임(판결 vs 관점)을 따른다. agent-to-agent rec·MCP 노출 수치를 Virtue 성과 기준으로 복사 금지.
