Virtue 결과 카드 직후 30초 행동 감사표

AI 판정 결과 카드(deed_judged) 직후의 행동 흐름을 잡별로 활성화/정상/보류/마찰로 읽는 내부 판독표. 신규 계측·발송·코드 변경 0.

01 🔴 무엇이 문제였나
deed_judged 발화는 결과 카드가 생성됐다는 사실일 뿐, 사용자가 이해·수용했는지, 저장·재시도·종료 중 무엇이 자연스러운 다음 행동인지 말해주지 않는다. 특히 J3는 저장 없이 닫혀도 정상, J1/J2/J4는 저장 뒤 누적 payoff로 못 이어지면 첫 응답 흐름이 끊긴다. 결과 직후 행동을 세션 전체와 섞어 읽으면 deed_save_capped·무저장 종료·반복 reroll을 가치 부재/이탈/불신으로 오독하기 쉽다.
02 ✅ 어떻게 해결하나
결과 카드(deed_judged:106)를 T0로 두고 직후 30초를 별도 판독 단위로 고정한 감사표를 docs-only로 추가했다. 같은 결과 카드가 J3엔 도착점, J1/J2/J4엔 통과점이라 직후 행동의 부호가 잡마다 뒤집힘을 명시하고, 보내면 안 되는 조건·바꾸면 안 되는 조건까지 못박았다.
  1. 결과 직후 첫 행동을 J1~J4 × 활성화/정상/보류/마찰 4칸으로 분류(§3) — 기존 이벤트 앵커만 매핑.
  2. "30초"는 계측이 아니라 수기 관찰 프레임(타이머·duration 이벤트 0)임을 못박음.
  3. do-not-send(발송 기본값 "보내지 않음", approval-needed) · do-not-change(코드·카피·이벤트 0)를 §5에 분리 고정.
  4. first value 매핑·deed_save_capped=availability/friction 재정의 0, event anchor drift 0, code diff 0, conflict marker 0.

이번에 새로 배운 것

  • 가치 전달은 결과 이벤트 발화가 아니라 직후 행동 흐름으로 드러난다(Mixpanel post-response flow 렌즈).
  • 같은 결과 카드가 J3엔 도착점·J1/J2/J4엔 통과점이라 "결과 직후 행동"의 부호가 잡마다 뒤집힌다.
  • 결과 직후 30초는 세션 전체와 분리된 판독 단위이며 "30초"는 계측이 아니라 관찰 프레임. on-instrument는 save/reroll/cap/종료뿐, 나머지는 off-instrument 손기록.
  • 읽기와 발송·변경은 별개 — 둘 다 기본값 "하지 않음".
