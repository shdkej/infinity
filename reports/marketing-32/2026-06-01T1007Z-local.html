Virtue 첫 입력 기본값 / 예시 / placeholder 감사표

Amplitude의 agent default-prompt 렌즈("기본값/placeholder가 첫 요청과 후속 행동을 설계한다")를 Virtue /add 첫 입력 유도의 잡별 감사로 번역한 실행 로그.

01 무엇이 문제였나
AI 제품의 첫 입력 기본값이 잡을 부르는 방향을 모른 채 후속 행동만 읽으면, 같은 중립 placeholder가 J1~J4를 구분 없이 부르는데도 "기본값이 좋다/나쁘다"를 잘못 단정하게 된다.
02 어떻게 해결하나
첫 입력 기본값 감사표를 추가해 /add·홈의 실재 유도 문구(D1~D9)와 부재한 예시·추천 질문을 J1~J4별로 가르고, "두 번째 메시지"를 잡별 두 번째 행동(J3=deed_rerolled/다른 입력, 나머지=deed_saved)으로 번역했다.

학습 루프 · 원장
  • 계승한 기준: first value 매핑(J1/J2/J4=deed_saved, J3=deed_judged) 재정의 0 · 마찰 부호 잡별 반전(AI 대기=J3 가치/J1·J4 마찰) · J3 저장 없는 종료=정상 · availability≠value(deed_save_capped upgrade 환산 금지) · 트래픽 분류 선행/prelaunch 비결정 등급.
  • 이번에 새로 배운 것: Virtue 첫 입력 기본값은 예시·추천 질문 0의 "질문형 placeholder + 빈 슬롯" 단일 패턴이다. "기능 설명형 기본값"(support-bot 유도)은 구조적 부재라 출처노트 권고와 우연히 정렬하지만, 중립성 탓에 잡별 조향도 0이다. 첫 입력 단계에서 J3·J2가 가장 약하게 불리고, 런타임 mock 모드 라벨이 J3 첫 인상을 낮춘다.
  • 다음 Marketer에게 넘길 규칙: 첫 입력을 읽을 때 "어떤 기본값(D-코드)이 이 잡을 불렀는가"를 먼저 분리한 뒤 후속 행동을 본다. "두 번째 메시지"는 잡별 두 번째 행동으로 번역하고 J3엔 저장을 기대하지 않는다(deed_rerolled/다른 입력=정상). 전역 예시/placeholder 최적화 금지 — 한 잡을 살리는 예시가 다른 잡을 구경/support-bot 모드로 끌 수 있으니 조향은 잡별로, 반드시 관찰 후.
  • MARKETING_LEARNINGS.md 승격 후보: "첫 입력 기본값/placeholder/예시는 잡을 부르는 조향 장치이며, Virtue는 예시 0의 중립 패턴이라 조향이 없다. 첫 입력 출처를 분리하지 않고 후속 행동을 읽지 않는다. '두 번째 행동'은 잡별로 다르다(J3=재판정/다른 입력, 나머지=저장)." → 본 실행에서 "First-Input Defaults Steer The Job" 기준으로 승격.
