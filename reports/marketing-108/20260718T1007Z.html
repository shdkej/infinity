첫 가치 경로 관점의 온보딩 관찰 companion 감사

Appcues 온보딩 노트의 시스템 관점을 Virtue 첫 10명 수기 관찰표에 붙였다.

01 무엇이 문제였나
기존 companion은 첫 사용자 언어와 guided break를 잘 읽지만, 사용자 목표에서 잡별 첫 가치 화면, 가치 직전 막힘, 다음 행동 명료성까지 한 경로로 묶는 칸이 더 필요했다.
02 어떻게 해결하나
수기 first-value path 감사표를 새 artifact로 만들고 J1/J3/J4 샘플 판독을 추가했다. production code, deploy, tracking, public copy 변경은 하지 않았다.
핵심 내용 · 리서치 본문
핵심 발견
  1. 온보딩은 기능 안내가 아니라 사용자 목표에서 첫 가치까지의 경로이므로, 관찰표도 목표·도착 화면·막힘·다음 행동을 같은 행에서 읽어야 한다.
  2. Virtue의 first value는 잡별로 다르다. J1/J2/J4는 저장 후, J3는 AI 결과 카드에서 닫히므로 저장 없는 J3 종료는 정상 후보다.
  3. 막힘은 바로 UI 변경 후보가 아니라 B-LOST, B-MISMATCH, B-AVAIL, B-NORMAL로 나누는 수기 판독 대상이다.
권장: 첫 10명 관찰 때 새 칸을 기존 ask script 옆에 붙이고, 반복 blocker가 보일 때만 별도 proposal intent로 UI/copy/tracking 후보를 분리한다.
근거 · 소스

Appcues source note, 기존 marketing-47 첫 사용자 ask script, marketing-51 guided first-value 감사표, MARKETING_LEARNINGS의 first value 및 prelaunch boundary.

다음 판단

No continuation. 실제 사용자 관찰 데이터가 들어오면 blocker 반복 여부만 별도 판단한다.

산출물 상세
추가 칸역할
user_goal_before_session회사가 보여주고 싶은 기능이 아니라 사용자의 목표에서 경로를 시작한다.
first_value_screen_reached잡별 첫 가치 도착 화면을 실제 세션 흐름으로 남긴다.
pre_value_blocker가치 직전 막힘을 구간과 성격으로 분리한다.
next_action_clarity_quote첫 가치 직후 다음 행동이 사용자 말로 나오는지 본다.

샘플 판독은 J1, J3, J4에 적용했다. 특히 J3는 deed_judged 도착 후 저장 없이 닫아도 정상 종료로 기록할 수 있게 분리했다.
