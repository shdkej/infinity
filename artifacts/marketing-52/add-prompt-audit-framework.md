# Virtue /add 초기 프롬프트 디자인 감사 프레임워크

> marketing-52 prepare 단계 산출물. 실제 분류는 local execution에서 수행한다.

## 감사 범위

Virtue `/add` flow에서 사용자가 마주치는 모든 텍스트:
- 페이지 헤더 / 타이틀
- Input placeholder 텍스트
- 힌트 / 서브텍스트 / 안내 문구
- 버튼 레이블 (제출, 취소, 재시도 등)
- AI system prompt 중 사용자-표면 요소
- 결과 카드 직전/직후 텍스트
- 에러/상태 메시지

## 1단계: 3-카테고리 분류

각 텍스트를 다음 중 하나로 분류한다:

| 카테고리 | 정의 | 예시 |
|---------|------|------|
| **A: UI 안내형 (Bumper)** | 기능 사용법, 입력 형식, 글자 수, 예시 포맷 설명 | "최소 20자 이상 입력하세요", "예: 오늘 운동을 했어요" |
| **B: 의도 확인형 (Steering)** | 사용자가 무엇을 하려는지 확인 / 잡별 방향 힌트 | "오늘 뭐 했어요?", "어떤 하루였나요?" |
| **C: 결과 지향형 (Result-first)** | AI 판정/결과를 빠르게 얻도록 맥락 수집 안내 | "한 줄로 오늘 핵심을 써보세요" |

분류 기준:
- 텍스트가 **기능 작동법을 설명**하면 → A
- 텍스트가 **사용자의 오늘 경험**을 묻거나 방향을 주면 → B
- 텍스트가 **AI 판정 품질**을 높이는 맥락을 유도하면 → C

## 2단계: 동사 프레임 분석 (m45 기준)

각 텍스트에서 **동사/명사** 프레임을 점검한다:

| 프레임 | 신호 언어 | 위험 |
|--------|----------|------|
| **판결 프레임** | 채점, 판정, 평가, 분석, 심판, 점수 | AI = 결정자 → 사용자 행위성 약화 |
| **관점 프레임** | 본, 읽은, 보여주기, 정리한, 함께 보자 | AI = 해석 제공자 → 마지막 선택은 사용자 |
| **혼재** | 같은 flow에서 두 프레임이 섞임 | m45의 핵심 위험: 불일치 → 결정 위임 오인 |

체크 포인트:
- [ ] 버튼 레이블에 판결 동사가 있는가?
- [ ] 헤더/타이틀에 관점 동사가 있는가?
- [ ] 같은 flow 내에서 프레임이 바뀌는가?

## 3단계: 잡별 조향 효과 평가 (m32 기준)

현재 placeholder/안내가 어떤 잡을 우선 부르는가?

| 잡 | First Value | 현재 조향 여부 |
|----|------------|---------------|
| J1: 완료/성취 기록 | deed_saved | ? |
| J2: 성장/레벨업 | deed_saved (누적) | ? |
| J3: AI 판정 받기 | deed_judged | ? |
| J4: 회고/복기 | deed_saved | ? |

단일 중립 placeholder(`뭐 했어요?`)는 모든 잡을 동일하게 부르지만,
m32에 따르면 J3(판정 받기)와 J2(누적 성장)가 가장 약하게 조향된다.

## 4단계: Guided First-Value 4구간 매핑 (m51 기준)

`/add` flow를 4구간으로 나누고 각 구간의 프롬프트가 어디에 속하는지 확인:

```
[첫 입력 전] → [AI 대기] → [결과 해석] → [저장/종료]
     ↑               ↑            ↑              ↑
  placeholder     loading      카드 텍스트    저장 버튼/힌트
  힌트/서브텍스트   메시지       재시도 유도    종료 문구
```

각 구간에서:
- B-LOST(길 잃음) 가능성이 있는 구간은 어디인가?
- 현재 A(UI 안내형)가 없어도 되는 구간에 배치돼 있는가?
- 결과 해석 구간에서 저장 유도 범퍼가 J3에 잘못 붙어있는가?

## 5단계: 개선 후보 작성 (proposal-only)

분류 결과를 바탕으로:

1. **제거 후보 (A→없음)**: first value 도달을 막는 UI 안내형 텍스트
2. **전환 후보 (A→C)**: UI 설명을 결과 지향 맥락 유도로 바꿀 수 있는 텍스트
3. **프레임 정렬 후보 (판결→관점)**: 동사 프레임 교체가 필요한 텍스트
4. **잡별 후보 (중립→조향)**: J3/J2 진입을 강화할 선택적 조향 텍스트

**모든 개선 후보는 proposal-only.** 공개 카피 배포, 코드 수정, 프로덕션 반영은 approval-needed.
