# 기록에서 출판으로 이어지는 작업 시스템 비교

## 목적

`research-21`의 실패 조건은 "위인전식 일화"로 흐르거나 도구 추천 목록으로 끝나는 것이다. 아래 비교는 각 사례를 `기록 방식 -> 정리 방식 -> 확인/검증 방식 -> 출판/결과물 변환 방식`으로 환원해, 실제 운영 구조만 뽑아내는 데 초점을 둔다.

## 실패한 단순화와 이번 정리의 차이

- 단순화: "천재라서 메모를 많이 했다"
- 이번 정리: 기록이 결과물로 바뀌는 경로에는 반복적으로 `채집`, `중간 구조화`, `검증`, `선형 결과물 조립`의 4단계가 있었다.

## 공통 패턴 6개

1. 기록은 대부분 "한 종류"가 아니었다. 읽기 메모, 초고, 편지, 관찰 기록, 카드가 병렬로 존재했다.
2. 실제 차이는 기록량이 아니라 중간 구조화 층에 있었다. 목록, 카드, 연결 ID, 읽기 노트, 파일 묶음이 그 역할을 했다.
3. 검증은 별도 QA 단계라기보다 기록 사이 교차 대조였다. 편지와 초고, 읽기 노트와 출판본, 카드와 수정 흔적이 서로 증거가 됐다.
4. 결과물은 대개 기록의 "요약본"이 아니라 기록망을 선형 독서물로 압축한 버전이었다.
5. 장기 프로젝트일수록 하루 기록과 최종 결과물 사이에 최소 한 번 이상 재배열 단계가 있었다.
6. 완성본 직전에는 항상 "무엇을 버리고 무엇을 전면에 둘지"를 정하는 편집 층이 나타났다.

## 사례별 짧은 해석

### 아인슈타인

핵심은 아이디어 노트 자체보다, 같은 시기 편지와 원고를 함께 읽을 때 사고의 진짜 전개가 보인다는 점이다. 즉 개인 기록 시스템에서도 "오늘의 생각"만 남기면 부족하고, 동시기 질문·반박·대응을 함께 남겨야 나중에 결과물로 전환된다.

### 다윈

다윈은 기록을 즉시 출판하지 않았다. 관찰, 읽기, 왕복 서신이 오래 쌓이고 다시 배열된 뒤 책으로 압축됐다. Infinity 관점에서는 주간 정리 없이 일일 기록만 쌓는 구조가 가장 위험하다는 뜻이다.

### 울프

울프의 reading notebook은 단순 독서노트가 아니라 "작품별 연구 저장소"에 가까웠다. 읽은 근거가 남아 있어서 나중에 비평과 소설의 재료가 어떻게 흘러갔는지 추적 가능했다. 따라서 메모는 감상문보다 출처 추적 가능성이 중요하다.

### 나보코프

나보코프의 강점은 비선형 조각을 카드로 보존해, 쓰는 순서와 읽히는 순서를 분리한 점이다. 긴 글을 한 파일에서 위에서 아래로만 키우는 방식은 구조 수정 비용이 크다.

### 루만

루만은 노트 축적보다 연결된 재진입 구조를 만들었다. 메모 하나가 끝이 아니라 다음 메모를 부르는 주소가 중요했다. 개인 지식 시스템은 폴더 정리보다 "다음에 어디로 이어질지"가 핵심임을 보여 준다.

### 벤야민

벤야민 사례는 "정리된 자료 묶음" 자체도 산출물 직전의 유효한 상태임을 보여 준다. 항상 완벽한 완성문만 목표로 잡으면 축적이 끊긴다.

## 마스터님 / SAM / Infinity용 현실적 기록 루프

### 1. 일일 기록: 최소 단위 3종만 남긴다

- `capture`: 관찰, 문장, 링크, 사실, 대화에서 건진 원재료
- `claim`: 오늘 떠오른 가설이나 판단 1줄
- `open_loop`: 아직 확인 안 된 질문 1줄

하루에 많이 쓰는 것보다 세 종류를 구분해 남기는 편이 중요하다.

### 2. 주간 정리: "주제별 묶음" 3개만 만든다

- 이번 주 기록에서 반복된 주제 3개를 뽑는다
- 각 주제마다 `근거 메모`, `현재 판단`, `빈칸/반례`를 3칸으로 정리한다
- 이 단계는 루만식 연결과 다윈식 재배열에 해당한다

### 3. 월간 산출물: 묶음 하나를 선형 결과물로 바꾼다

- 주간 묶음 중 하나를 골라 `짧은 글`, `리서치 메모`, `의사결정 문서`, `뉴스레터` 중 하나로 변환한다
- 중요한 것은 "새로 쓰기"가 아니라 이미 있는 메모망을 선형화하는 것이다

### 4. 검증 규칙: 완성 전 최소 2종 교차 확인

- 주장 하나당 근거 2종 이상: 원문/링크 + 내 메모, 혹은 기록 + 대화
- 출처 불명 문장, 기억 의존 요약, 단일 스크린샷 기반 판단은 월간 산출물에서 제외

### 5. 보존 규칙: 결과물보다 중간 묶음을 남긴다

- 최종 글만 보존하지 말고, 그 글이 나온 주간 묶음도 남긴다
- 그래야 같은 주제로 다음 글을 만들 때 다시 0부터 시작하지 않는다

## 바로 적용 가능한 최소 절차

1. 매일 `capture / claim / open_loop` 3줄 기록
2. 매주 금요일 30분 동안 주제 3개 묶기
3. 매월 마지막 주에 묶음 1개를 공개/반공개 결과물 1개로 변환
4. 결과물마다 "어떤 기록 묶음에서 나왔는지" 링크 남기기
