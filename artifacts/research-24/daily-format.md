# 일일 기록 3줄 포맷

_research-24 산출물 · 기록→출판 루프 최소 적용안_

---

## 한 눈에 보기

```
capture: [출처] 오늘 만난 원재료
claim:   오늘 내린 판단 1줄
open_loop: 아직 모르는 질문 1줄
```

세 필드는 "있었던 것 / 내린 것 / 모르는 것"이다. 의미가 겹치지 않는다.

---

## 필드 정의

### capture — 오늘 만난 것

오늘 실제로 본·들은·읽은 원재료. 해석 없이, 출처와 함께.

**형식**
```
capture: [출처] 원문 또는 사실 단편
```

**예시**
```
capture: [LinkedIn] "GenAI 도입 초기 팀의 65%는 6개월 안에 사용률이 반 이하로 줄었다"
capture: [팀 대화] "회의보다 슬랙 스레드가 의사결정이 더 빠르다고 느낀다"
```

**금지**
- "~인 것 같다" 해석 섞기
- 출처 없는 기억 의존 요약
- 오늘 떠오른 생각 → claim으로

---

### claim — 오늘 내린 판단

오늘 내가 내린 판단 또는 생각의 변화. 단 1줄. capture 없어도 쓸 수 있다.

**형식**
```
claim: [판단 동사] 내용
```

**예시**
```
claim: 사용자 인터뷰보다 실제 행동 로그가 더 정직하다고 바꿨다
claim: Threads 초안을 밤에 쓰면 다음날 읽을 때 이상하다
```

**금지**
- "SAM이 ~해줘야 한다" 운영 지시 → open_loop [SAM]으로
- capture 내용을 그냥 반복하는 요약

---

### open_loop — 아직 모르는 것

오늘 생긴 질문 또는 다음에 확인해야 할 사항. 단 1줄. **없으면 비워도 된다.**

**형식**
```
open_loop: ~인가? / ~을 확인해야 한다
open_loop: ~인가? [SAM]   ← SAM이 다음 Heartbeat에서 조사
```

**예시**
```
open_loop: 리뷰 답변 속도와 별점 사이에 실제 상관관계가 있는가?
open_loop: Virtue D7 이상 지속 사용자의 공통 행동이 무엇인지 확인 필요 [SAM]
```

**SAM 처리 구분**
- 개인 판단/가설 질문 → open_loop에 기록, 사용자가 직접 추적
- 자동화 가능한 조사 → open_loop [SAM] 접두어 추가, 다음 Heartbeat 처리 후보

---

## 필드 간 경계 규칙

| 상황 | 올바른 필드 |
|---|---|
| 오늘 읽은 기사나 대화 내용 | capture |
| 그 내용을 읽고 든 내 생각 | claim |
| 그 생각이 맞는지 확인하고 싶은 것 | open_loop |
| SAM이 다음 Heartbeat에 조사해줬으면 하는 것 | open_loop [SAM] |
| SAM에게 뭔가 시키고 싶은 것 | open_loop [SAM] (claim 아님) |

---

## 산출물 연결 규칙

### 회고 (주간)
- **읽는 필드**: `claim` 위주
- **방법**: 이번 주 claim들을 모아 "이번 주 나는 어떤 판단을 바꿨나"로 정리
- **예외**: 판단을 뒷받침하는 capture 인용 1~2개 가능

### Threads 후보
- **읽는 필드**: `claim` → `capture` 순서
- **핵심 규칙**: Threads는 반드시 claim(사용자 판단)에서 출발한다. capture 단독으로 Threads가 되지 않는다.
- **방법**: claim 1줄을 첫 문장으로, 근거 capture를 뒤에 붙인다

### 카드뉴스 입력
- **읽는 필드**: `claim` + `capture` 세트
- **방법**: claim이 주제, capture가 근거. open_loop가 있으면 마지막 카드에 "다음 질문"으로 사용 가능

## 하루 끝 기록 예시 (3분 목표)

```
date: 2026-06-29

capture: [LinkedIn] "GenAI 도입 초기 팀의 65%는 6개월 안에 사용률이 반 이하로 줄었다"
claim: 도구 도입은 습관 설계가 빠지면 자연감소한다고 확신이 생겼다
open_loop: Virtue D7 이상 지속 사용자의 공통 행동이 무엇인지 확인 필요 [SAM]
```

## 반드시 하지 말아야 할 것

- 오늘 날짜 없이 기록하기
- capture와 claim을 같은 줄에 섞기
- 세 줄을 모두 채워야 한다는 부담 (open_loop는 없으면 비워도 됨)
- SAM 운영 지시를 claim에 넣기
- 출처 없이 capture 쓰기
