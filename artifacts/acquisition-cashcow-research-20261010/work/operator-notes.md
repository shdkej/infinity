## Commit / push / remote proof 운영 체크리스트

원격 반영은 보고서와 artifact를 정본 저장소에 안전하게 반영하는 별도 운영 단계다. 외부 매물 플랫폼에 쓰기 작업을 하는 것이 아니다.

1. 대상 저장소와 브랜치를 확인한다: `git status --short --branch`, `git remote -v`.
2. 기존 사용자 변경·미추적 파일을 보존하고 이번 intent 대상 경로만 명시적으로 확인한다.
3. 대상 diff를 검토한다: `git diff -- artifacts/acquisition-cashcow-research-20261010/`.
4. 시크릿, 인증 헤더, 개인 연락처, 비공개 원문이 없는지 검사한다. 문제 발견 시 push하지 않는다.
5. 로컬 문법/링크/필드 검증 후 대상 artifact/report만 targeted commit한다. `git add -A`와 force push는 금지한다.
6. 커밋 메시지에 intent id와 산출물 목적을 포함하고 commit SHA를 기록한다.
7. 승인된 원격 브랜치로 non-force push한다. 권한 오류·dirty 상태·충돌이면 기존 변경을 덮지 말고 Waiting으로 전환한다.
8. push 후 local `HEAD` SHA와 `origin/<branch>` SHA 일치 여부, `git status --short`, remote URL/branch를 확인한다.
9. `work/remote-proof.txt`에 UTC 시각, 저장소 경로, 브랜치, commit SHA, push 결과, 원격 SHA, dirty 파일, 검증 명령을 남긴다.
10. 원격 확인 전 완료/Archive로 보고하지 않는다. Red 검증(`work/red/final-review.md`)과 승인 경계 결과도 확인한다.

## 차단·재개 조건

- 원격 인증/권한이 없거나 저장소가 dirty하여 대상 변경만 안전하게 분리할 수 없으면 push하지 않는다.
- 원격 브랜치가 예상과 다르거나 non-force push가 거부되면 사용자 승인 없이 우회하지 않는다.
- 재개 조건은 (a) 승인된 저장소·브랜치, (b) 대상 파일 범위, (c) 기존 변경 보존, (d) 원격 SHA 검증 가능 상태다.
