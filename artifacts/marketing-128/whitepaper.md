# marketing-128 일일 운영 백서

- 목적: 실제 구매·사용 근거가 있는 물건으로 Threads 실험을 반복하고, 게시 후 72시간 내 `저장` 또는 `구체적 답글`을 높이는가 확인한다.
- 범위: 내부 리서치, 후보 선출, 초안, 측정표, 백서 업데이트. 공개 게시·공개 Sharelink 공유·로그인/계정 변경은 사용자 명시 승인 전 금지.
- 1차 판정: 유효 반응 = 저장 또는 내용이 있는 답글. 좋아요·노출·클릭·수익은 보조 신호다.

## 1. 매일의 운영 루프

1. **근거 재확인**: 오늘 다룰 물건이 실제 구매 또는 실제 사용 장면에 연결되는지 원본 기록과 대조한다. 상품 검색 결과만 있는 후보는 탈락시키며, 구매 기록만 있으면 사용 후기가 아닌 구매·준비 사실만 쓴다.
2. **후보 선출**: 구매 기록을 그대로 한 게시물로 복사하지 않는다. 한 번에 구매한 묶음도 즉시 개별 상품 후보로 나눠 계속 진행한다. 서로 다른 문제를 해결하는 상품은 같은 구매 기록에 있어도 별도 후보·별도 게시물로 분리한다. 상품 동일성이 아직 덜 확인된 부분은 후보를 멈추는 이유가 아니라 `purchase_record_only`와 낮은 주장 상한으로 표시하는 이유다.
3. **훅 작성**: 같은 후보에 서로 다른 각도 2개를 만든다. 개인 사건·숫자·관찰·선택 중 하나만 쓴다.
4. **본문 작성**: 실제 장면 → 선택/사용 이유 → 아직 모르는 점 또는 조건 → 독자가 답할 수 있는 구체 질문 순서로 5~9줄을 만든다.
5. **게시 전 검수**: 근거, 과장, 고지, 링크, 가격/재고, 사용자 승인 상태를 확인한다. 승인 전에는 초안으로만 보관한다.
6. **72시간 측정**: 게시 시각을 기준으로 30~90분/24h/48h/72h 저장·구체적 답글·클릭·수익을 기록한다.
7. **백서 업데이트**: 반응이 있었던 이유를 단정하지 말고, 관찰된 문장·후킹 각도·반증된 가설·다음 변경 한 가지를 기록한다.

## 2. 후보 평가표

각 항목 0~2점. 총 8점 미만은 보류한다. 점수는 상품의 인기도가 아니라 콘텐츠 실험 가능성을 판정한다.

| 항목 | 0점 | 1점 | 2점 |
|---|---|---|---|
| 실제 구매/사용 근거 | 검색·추정만 있음 | 구매 기록만 있음 | 구매 기록과 구체적 사용/준비 장면 모두 있음 |
| 불편의 구체성 | 범용 장점 | 상황은 있으나 흐림 | 장소·행동·문제가 한 장면으로 보임 |
| 선택 이유 | 가격/인기 반복 | 일부 기준 있음 | 다른 선택을 하지 않은 이유까지 말할 수 있음 |
| 반응 질문성 | 예/아니오 | 경험 공유 가능 | 독자가 자기 사례·반대 의견을 구체적으로 답할 수 있음 |

현재 1차 후보는 marketing-123의 원본 기록을 다시 대조하되, 묶음명을 그대로 한 글의 제목으로 쓰지 않고 상품별 후보로 분리한다. 후보는 구매 기록에 나온 상품명 수준에서 바로 만들고, 실제 상품·옵션·Sharelink 동일성이 확인되기 전까지는 구매·준비 사실만 말한다. `압축파우치`, `65W GaN 충전기`처럼 원본 기록에 없는 이름은 재사용하지 않는다.

**개별 게시 단위 규칙:** `여행용 파우치와 칫솔`, `멀티플러그와 종이세제`, `손톱깎이·수건·빨랫줄`은 구매 기록의 묶음 표현이다. 한 기록에 같이 적혀 있다는 이유만으로 한 글에 묶지 않는다. 먼저 상품별 후보와 상품별 훅을 만들고, 같은 문제·같은 장면을 공유한다는 근거가 있을 때만 묶음 게시를 별도 실험으로 승인한다.

검색으로 찾은 Toss Shopping 상품은 **사용 근거가 아니라 후보 링크 탐색 자료**다. 공개 초안에 넣기 전에 회원 화면에서 정확한 상품·옵션·가격·재고·배송을 다시 확인한다.

실제 경험 후보와 제휴 후보가 다르면 `affiliate_match=substitute|mismatch`로 표시하고 “실제 구매품”처럼 쓰지 않는다. 불일치·미확인 링크는 초안에 삽입하지 않으며, 대체 후보로 사용할 때만 그 사실을 명시한다. 원본 기록은 실행 시점 읽기 전용 스냅샷과 해시를 남긴다.

## 3. 훅과 본문 규칙

- 첫 줄은 제품명이 아니라 장면 또는 불편으로 시작한다.
- 한 글에 주장 하나만 둔다. `여행이 편해진다`처럼 넓은 약속은 쓰지 않는다.
- 실제로 확인한 사실과 아직 확인하지 않은 사실을 분리한다. 구매 기록만으로 사용 후기나 효과를 발명하지 않는다.
- `오늘은 X보다 Y`, 격언, 독자에게 훈계하는 일반화, 반복되는 `A했는데 정작 B` 골격을 피한다.
- `좋다/필수/인생템/추천` 대신 무엇을 줄였고 어떤 조건에서 불편했는지 쓴다.
- 경제적 이해관계 고지는 링크보다 앞에 둔다. 링크가 없으면 고지 위치만 `[고지문 삽입]`으로 표시한다.
- 게시 전에는 같은 후보의 훅 2개 중 하나만 선택한다. 나머지는 다음 변형으로 보관한다.

## 4. 게시 전 검수

`근거 있음` / `사실·추정 분리` / `과장 없음` / `고지 선행` / `링크·가격·재고 재확인` / `사용자 공개 승인`을 모두 통과해야 게시 가능하다. 하나라도 빠지면 `HOLD`다.

판정 규칙: 72시간 유효 반응이 있고 후보·훅 근거가 재현되면 `continue`; 반응은 있으나 근거/훅 설명이 약하면 `change`; 실제 사용 근거 또는 유효 반응이 없으면 `hold`. 작은 3개 표본으로 안정적 전환율이나 수익성을 선언하지 않는다.

## 6. 일일 학습 로그 형식

`date / post_id / observed_fact / hook_variant / valid_response / secondary_signal / failed_assumption / one_change / evidence_source`만 남긴다. 다음 날에는 가장 큰 불확실성 하나만 바꾼다. 백서는 측정표와 함께 버전업하고, 변경 이유를 한 줄로 기록한다.

운영 방식: 게시 결과는 `artifacts/marketing-128/metrics.jsonl`에 한 줄씩 기록하고, Infinity 일일 디스패처가 새 기록을 읽어 `observed_fact`, `valid_response`, `failed_assumption`, `one_change`를 백서 학습 로그에 반영한다. 사용자는 매일 백서를 직접 편집하지 않는다. 다만 외부 게시·계정 접근·공개 링크 공유는 자동화하지 않고 사용자 승인을 유지한다.

계승한 기준: marketing-123의 실제 구매 근거 우선, 공개 승인 경계, 고지 선행, 작은 표본의 과대해석 금지. 이번에 새로 둔 기준: 후보 4항목 점수표, 훅 2변형, 72시간 시점별 기록, 하루 한 변경. 승격 후보: 실제 게시 데이터가 3회 이상 쌓인 뒤 훅 각도별 재현성 규칙을 별도 학습 원장에 검토한다.

## 7. 중단·정정 경계

가격·옵션·재고 불일치, 잘못된 링크, 과장된 사용 후기, 고지 누락은 즉시 `hold`다. 게시 후 문제가 생겨도 먼저 내부 링크 중지와 후속 게시 보류를 하고, 공개 정정·삭제는 별도 사용자 승인을 받은 뒤에만 한다.
