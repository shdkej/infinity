# Virtue 첫 세션 3-스크린 가치 경로 감사표

> 내부 감사 브리프 · prelaunch 전용 · 코드/이벤트/카피 변경 금지

## 목적

첫 10–20명 관찰 전, J1–J4별 "첫 약속 → 첫 행동 → 첫 가치 확인" 경로가 세 화면 안에 닫히는지 점검한다. 닫히지 않는 구간과 기존 이벤트 연결을 명시하여, 유저 획득·활성화·리텐션 해석에 쓸 공통 언어를 확정한다.

**배경 맥락**: Lenny Distilled 온보딩 원칙(온보딩 = 기능 설명이 아닌 즉시 가치 전달)과 Amplitude 벤치마크(early value → early retention 상관)를 근거로, 가치 경로가 화면 단위로 닫히는지 내부 감사한다.

---

## 3-스크린 정의

| 화면 | 경로 | 역할 |
|------|------|------|
| **S1 홈** | `/` | 첫 약속 — "이 앱이 내게 줄 것"을 인식하는 순간 |
| **S2 추가** | `/add` | 첫 행동 — 덕행 입력 시작 (`add_flow_started` 발화) |
| **S3 결과** | 저장·평가 완료 화면 | 첫 가치 확인 — `deed_saved` 또는 `deed_judged` |

**닫힌다** = S1의 약속과 S3의 가치 확인이 하나의 세션 안에서 연결된다.  
**닫히지 않는다** = S3에 도달해도 약속한 가치를 확인할 수 없거나, S3 자체에 도달하지 못한다.

## J1–J4별 3-스크린 가치 경로

### J1 기록형 — "오늘 한 일을 기록으로 남기고 싶다"

| 단계 | 화면 | 내용 | 이벤트 |
|------|------|------|--------|
| 첫 약속 | S1 `/` | 빈 상태 CTA — "덕행을 기록하세요" | — |
| 첫 행동 | S2 `/add` | 덕행 내용 입력 후 제출 | `add_flow_started` |
| 첫 가치 확인 | S3 결과 | 저장된 덕행 카드 — "오늘의 기록이 남았다" | `deed_saved` |

**3화면 닫힘**: ✅ 닫힘

**갭 / 주의**
- S1 빈 상태 카피가 "기록"을 약속하지 않으면 S2 진입 동기가 희석됨
- `deed_judged` 대기 시간이 S3 로딩을 늘리면 J1에게 불필요한 마찰 발생 (J1 aha = `deed_saved`, AI 평가 대기는 J3 전용 good-friction)
- iOS: `deed_saved` 발화는 확인됨, `level_up_viewed` 미지원이어도 J1 경로에 영향 없음

---

### J2 누적형 — "덕행을 쌓고 레벨을 올리고 싶다"

| 단계 | 화면 | 내용 | 이벤트 |
|------|------|------|--------|
| 첫 약속 | S1 `/` | 레벨·스트릭 표시 (초기값 0 또는 시작 상태) | — |
| 첫 행동 | S2 `/add` | 덕행 입력 후 저장 | `add_flow_started` |
| 첫 가치 확인 | S3 결과 | 저장 + 레벨업 화면 | `deed_saved` → `level_up_viewed` |

**3화면 닫힘**: ⚠️ 조건부 닫힘

**갭 / 주의**
- `level_up_viewed`는 누적 임계값 도달 시에만 발화. 첫 덕행으로 레벨업이 없으면 S3에서 누적 가치 확인 불가
- **3화면 미닫힘 구간**: 첫 덕행 저장 후 레벨업 미발생 → S3에서 "쌓고 있다"는 진행 상태 표시 없음
- S1 홈이 레벨/스트릭을 0부터 보여주면 J2 약속 전달 가능 (현재 구조 확인 필요)
- iOS: `level_up_viewed` 미지원 → iOS J2 경로는 web보다 더 취약. 첫 세션 이후 재방문 여부로 대체 관찰

---

### J3 AI 호기심형 — "AI가 내 행동을 어떻게 평가하는지 보고 싶다"

| 단계 | 화면 | 내용 | 이벤트 |
|------|------|------|--------|
| 첫 약속 | S1 `/` | AI 평가 앱임을 나타내는 시각 신호 | — |
| 첫 행동 | S2 `/add` | 덕행 입력 후 AI 평가 요청 | `add_flow_started` |
| 첫 가치 확인 | S3 결과 | AI 평가 결과 표시 | `deed_judged` |

**3화면 닫힘**: ⚠️ 조건부 닫힘

**갭 / 주의**
- `deed_judged`는 비동기 AI 호출. 응답 지연 시 S3가 pending 상태로 열려 있거나, 사용자가 화면을 벗어남
- **3화면 미닫힘 구간**: AI 평가 로딩 대기 → 같은 세션 내 `deed_judged` 미수신 시 가치 확인 불완결
- S1 홈에서 "AI 평가 앱"을 나타내는 신호 현재 약함 (competitive-alternatives-positioning-brief: J3는 `/add` 이전 사실상 신호 부재)
- J3 aha는 `deed_judged`이므로 `deed_saved`보다 먼저, 또는 동시에 표시되어야 S3에서 가치 확인 완결

---

### J4 회고형 — "지금까지 쌓아온 덕행을 돌아보고 싶다"

| 단계 | 화면 | 내용 | 이벤트 |
|------|------|------|--------|
| 첫 약속 | S1 `/` | 덕행 이력·회고 공간 (신규 사용자에게는 비어 있음) | — |
| 첫 행동 | S2 `/add` | 첫 덕행 입력 (회고할 최소 기록 생성) | `add_flow_started` |
| 첫 가치 확인 | S3 결과 | 첫 덕행 저장 완료 (단, "회고" 가치는 아직 없음) | `deed_saved` |

**3화면 닫힘**: ❌ 구조적 미닫힘

**갭 / 주의**
- 첫 세션에는 회고할 이력이 없음. J4 약속과 S3 가치(첫 기록) 사이의 단절은 구조적
- **3화면 미닫힘 구간**: S1 약속(회고)과 S3 가치(첫 기록) 사이 전체 — 첫 세션에서 J4 가치를 얻으려면 이미 덕행이 쌓여 있어야 함
- J4 활성화 마일스톤은 activation-milestone-ladder 기준으로 2회차 방문이 aha 시작점
- 첫 세션 J4 사용자에게 실질 가치는 "기록 시작" (J1과 동일). 첫 세션 전환율 해석 시 J4를 J1과 분리하지 않으면 왜곡

## Prelaunch 해석 금지선

- 3화면 미닫힘 구간은 **관찰 기준**이지 즉시 수정 지시가 아님
- J4 구조적 미닫힘은 버그가 아님 — 2회차 방문이 활성화 마일스톤
- `level_up_viewed` 미발화는 데이터 관찰 후 판단 (코드 수정 전)
- 첫 10–20명 세션 수가 적어 전환율 수치 판정 금지
- 이 문서는 내부 감사 브리프 — 카피·이벤트·코드·대시보드·외부 발송에 직접 반영 금지
