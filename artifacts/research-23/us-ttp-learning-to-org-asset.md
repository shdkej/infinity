# 미군 TTP는 어떻게 학습을 조직자산으로 바꾸는가

> research-23 | 2026-06-24 | 로컬 실행 리서치
> 후속 맥락: research-17 "미군 연구 시스템 구조 리서치"의 TTP 변환 축 심화

## 한 줄 결론

미군의 TTP 메커니즘은 "좋은 회고"가 아니라 **관찰을 표준 절차로 바꾸고, 그 절차를 다음 훈련에서 다시 검증하는 폐쇄 루프**다. 개인의 경험은 AAR과 관찰 보고로 포착되고, CALL/JLLIS 같은 lessons learned 계층에서 분석·축적되며, SOP/TTP·훈련 과제·교리·교육 과정으로 내려와 다시 현장에서 시험된다.

---

## 1. 전체 루프

```text
실전/훈련 사건
  -> AAR / 관찰 / best practice 포착
  -> CALL/JLLIS 축적과 root-cause/trend 분석
  -> SOP/TTP/훈련 과제/교리 초안으로 변환
  -> CTC/홈스테이션/PME에서 재훈련
  -> 다음 작전·훈련에서 검증
  -> 다시 AAR
```

이 루프의 핵심은 "기록했다"가 아니라 **다음 행동 표준이 바뀌었는가**다.

---

## 2. 단계별 메커니즘

| 단계 | 질문 | 산출물 | 조직자산화 방식 |
|---|---|---|---|
| 1. 사건 포착 | 실제로 무슨 일이 있었나 | AAR, 관찰, best practice, unit experience | 기억이 아니라 기록 가능한 원자료로 만든다 |
| 2. 차이 분석 | 계획·교리·현장 사이 어디가 어긋났나 | root cause, trend/theme, gap | 개인 탓이 아니라 반복 가능한 패턴으로 바꾼다 |
| 3. 지식 축적 | 이 교훈이 한 부대만의 일인가 | CALL/JLLIS entry, handbook, bulletin | 부대 밖에서도 찾을 수 있는 중앙 저장소에 올린다 |
| 4. 절차 변환 | 다음에는 어떻게 해야 하나 | SOP, TTP, checklist, task standard | 암묵지를 실행 문장으로 바꾼다 |
| 5. 훈련 재투입 | 새 절차가 몸에 붙는가 | training plan, rehearsal, CTC rotation, PME case | 문서가 아니라 반복 훈련으로 검증한다 |
| 6. 제도 반영 | 이게 전체 Army 기준을 바꿔야 하나 | doctrine update, POI, DOTMLPF-P change | 특정 부대의 요령을 제도/교리/교육으로 승격한다 |

---

## 3. 왜 TTP가 핵심 단위인가

TTP는 doctrine보다 작고, 개인 팁보다 크다.

| 층위 | 성격 | 약점 |
|---|---|---|
| 교리 doctrine | 원칙과 큰 작전 개념 | 현장 행동으로는 너무 추상적일 수 있음 |
| SOP/TTP | 반복 상황에서 쓸 절차·요령·판단 순서 | 너무 낡으면 현실과 어긋남 |
| 개인 경험 | 생생하고 구체적 | 전파되지 않으면 사라짐 |

그래서 TTP는 **현장 경험이 조직 표준으로 바뀌는 중간 포맷**이다. 좋은 TTP는 "누가 잘했다"가 아니라 "다음 부대도 같은 조건에서 따라 할 수 있는 절차"로 남는다.

---

## 4. 돌아가게 만드는 장치

### AAR는 입력 장치다

AAR는 단순 회고가 아니라 다음 훈련을 바꾸기 위한 입력 장치다. 핵심 질문은 대체로 `무엇을 하려 했나`, `무슨 일이 있었나`, `왜 차이가 났나`, `다음에는 무엇을 바꿀까`다. 여기서 액션이 안 나오면 조직자산으로 넘어가지 않는다.

### CALL/JLLIS는 압축 장치다

CALL은 Army Lessons Learned Program의 중심으로, tactical부터 theater/strategic 레벨까지 lessons learned를 수집·분석·배포·통합·보관한다. 개별 부대의 경험은 여기서 trend/theme, root-cause, gap으로 압축된다.

### SOP/TTP는 실행 장치다

분석 결과가 SOP/TTP로 바뀌면, 지식은 "읽을거리"가 아니라 "다음 훈련에서 검증할 행동 규칙"이 된다. 특히 tactical SOP는 반복되는 작전 기능을 표준화하되, 효과성을 잃지 않는 범위에서 절차로 고정한다.

### CTC/PME는 검증 장치다

Combat Training Center, 홈스테이션 훈련, PME는 바뀐 TTP가 실제로 작동하는지 다시 시험하는 공간이다. 이때 또 AAR가 발생하고, 루프가 닫힌다.

## 5. 개인/소규모 팀 적용판

| 미군 메커니즘 | 개인/팀 버전 |
|---|---|
| AAR | 작업 후 4문 기록: 의도 / 실제 / 차이 / 다음 변경 |
| CALL/JLLIS | 프로젝트별 lessons log 또는 wiki |
| SOP/TTP | 체크리스트, 프롬프트, 템플릿, 운영 규칙 |
| CTC/훈련 | 다음 실제 작업에서 새 절차를 의도적으로 써보기 |
| Doctrine/PME | 장기 운영 문서, 스킬, 온보딩 문서로 승격 |

개인에게 중요한 변환 기준은 하나다.

> 배운 것이 "좋은 생각"으로 남았는가, 아니면 다음 실행의 기본값을 바꿨는가?

---

## 6. SAM/Infinity 적용 루프

```text
작업/실패/사용자 피드백
  -> 짧은 AAR: 기대 / 실제 / 원인 / 다음 기본값
  -> memory 또는 system/docs에 교훈 기록
  -> 반복 가능하면 skill/workflow/cron prompt로 변환
  -> 다음 실행에서 검증
  -> 잘 맞으면 canonical docs로 승격
```

이번 대화에서 바로 적용되는 예시는 다음과 같다.

| 관찰 | TTP 변환 |
|---|---|
| 긴 요약은 읽기 어렵다 | 요약 기본 포맷을 섹션+표+구분선으로 고정 |
| 툴 큐레이션이 JSON 메타데이터에 치우쳤다 | 웹 상세/원문 근거 없으면 추천하지 않는 gate 추가 |
| 라우터 요약의 "긴급 차단" 표현이 불필요한 불안을 만들었다 | handoff성 진행 기록은 "진행 기록"으로 완화 |

이게 바로 TTP 변환이다. "다음엔 조심하겠습니다"가 아니라 **다음 실행을 바꾸는 규칙과 검수 gate**로 남기는 것.

## 요약

미군식 학습은 "회고 문화"가 아니라 **지식 공급망**이다.

1. 현장에서 관찰한다.
2. AAR로 차이를 드러낸다.
3. CALL/JLLIS가 패턴으로 압축한다.
4. SOP/TTP가 다음 행동으로 바꾼다.
5. 훈련·교육·교리에서 재검증한다.
6. 다시 현장으로 돌아가 갱신한다.

조직자산이 된다는 말은 결국 **다음 사람이 같은 상황에서 더 빨리, 덜 틀리게 행동할 수 있는 표준이 생긴다**는 뜻이다.
