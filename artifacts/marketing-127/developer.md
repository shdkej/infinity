# marketing-127 Developer — 브랜드 계정명 후보와 비점유 검증 설계

작성 기준: 2026-08-25 UTC  
범위: 브랜드 계정명 후보 발굴·검증 절차 설계  
외부 행동: 계정 생성, 핸들 선점, 프로필 변경, 로그인, DM, 예약·등록을 수행하지 않음

## 1. 불확실성 보존

현재 확인된 공개 근거는 `_archivenoh` 계정의 일부 게시물과, 여행 계획·AI·인간의 선택 시간을 관찰하는 캡션 1건이다. 이를 앱의 정식 제품명, 기능 목록, 고객군, 운영 주체, 법인명, 상표권, 출시 국가 또는 최종 포지셔닝으로 해석하지 않는다.

따라서 후보명은 **앱의 기능을 단정하는 이름이 아니라**, 현재 보이는 `기록 / 이동 / 선택 / 관찰 / 반복`이라는 소재에서 만든 탐색용 가설이다. 아래 후보의 ‘적합’은 계정 사용 가능이나 상표 안전을 의미하지 않으며, 실제 확인 전에는 모두 `미확인` 상태다.

확정 전에 반드시 분리해서 확인할 질문:

- 제품의 실제 범위가 여행 기록인지, 의사결정 도구인지, 콘텐츠 브랜드인지
- 브랜드를 개인 계정과 분리할지, `_archivenoh`를 모브랜드로 유지할지
- 1차 언어·시장(한국어, 영어, 다국어)과 발음 기준
- 앱·웹·뉴스레터·커뮤니티·상품으로 확장할 계획이 있는지
- 법인/상표 검색을 진행할 주체와 승인권자

## 2. 탐색 후보군

후보는 현재 정보에 맞는 세 가지 결을 섞었다. 한국어형은 정서와 기억성을, 영문 조합형은 핸들·도메인 확장성을, 조어형은 중복 회피 가능성을 시험하기 위한 것이다. 표의 핸들은 **예약 후보 표기일 뿐 가용성 확인 결과가 아니다.**

| # | 표시명 후보 | 의미 가설 | 핸들 표기 후보 | 초기 리스크/보류 이유 |
|---:|---|---|---|---|
| 1 | 다음 장면 | 기록 뒤의 다음 선택·행동 | `@nextscene` / `@next.scene` | 일반 명사 조합이라 중복 가능성이 높고 엔터테인먼트로 오인될 수 있음 |
| 2 | 선택의 여백 | 결정 전 잠시 관찰하는 공간 | `@choiceblank` / `@choice.blank` | `blank`가 공백·문구류 서비스로 읽힐 수 있음 |
| 3 | 여정의 기록실 | 여행과 아카이빙의 결합 | `@journeyarchive` | 여행 미디어·아카이브 서비스와의 의미 중복 가능성 |
| 4 | 작은 경로 | 큰 계획보다 작은 이동·실험 | `@smallroute` | 지도·물류·여행 앱으로 좁게 인식될 수 있음 |
| 5 | 느린 선택 | 속도보다 기준을 남긴다는 가설 | `@slowchoice` | ‘느림’이 성능 저하로 오해될 수 있고 발음은 쉬우나 확장 의미가 좁음 |
| 6 | 기록 후 다음 | 기록을 다음 행동으로 연결 | `@afterlog` | `after log`가 기술 로그 분석으로 읽힐 수 있음 |
| 7 | Trace & Turn | 흔적을 보고 방향을 바꾼다는 구조 | `@traceandturn` / `@trace.turn` | 영어 발음·철자 청취가 어렵고 `turn`의 교통 의미가 섞임 |
| 8 | Waynote | way + note, 이동 중 메모 | `@waynote` | 조어지만 기존 서비스·상표와의 충돌 가능성을 먼저 확인해야 함 |
| 9 | Choicelog | choice + log, 선택 기록 | `@choicelog` | 기능을 의사결정 로그로 과도하게 고정할 수 있음 |
| 10 | Roamark | roam + mark, 이동의 흔적 | `@roamark` | `roam`과 `mark`의 결합을 한 번에 이해하기 어려울 수 있음 |
| 11 | Pathmemo | path + memo, 경로 메모 | `@pathmemo` | 메모 앱·지도 앱과의 유사성이 높을 수 있음 |
| 12 | Stillway | 멈춤과 이동을 함께 표현 | `@stillway` | `still`의 정지 의미와 `way`가 추상적이며 기존 브랜드 여부 불명 |
| 13 | Frame Next | 장면을 프레임하고 다음을 고침 | `@framenext` | 사진·영상 편집 도구로 오인될 수 있음 |
| 14 | Curio Route | 궁금증에서 경로를 만든다는 가설 | `@curioroute` | `curio` 발음이 사람마다 달라지고 여행 서비스로 한정될 우려 |
| 15 | Archive Between | 기록과 다음 선택 사이 | `@archivebetween` | 길고 철자 오류 가능성이 높아 계정명으로는 약함 |
| 16 | Noonoh | `noh`를 보존한 짧은 조어 후보 | `@noonoh` | 기존 이름과의 관계를 설명해야 하며 발음이 `누노/눈오`로 갈릴 수 있음 |

### 우선 검토 순서(가용성 판단 아님)

1차 대화·브랜드 적합성 검토는 `Waynote`, `Roamark`, `다음 장면`, `선택의 여백`으로 시작한다. 이 네 개는 각각 조어형 2개와 한국어형 2개라서, 앱의 실제 포지셔닝이 밝혀졌을 때 어느 방향이 더 견고한지 비교하기 쉽다. `Choicelog`, `Pathmemo`, `Archive Between`은 기능·길이 리스크가 커 후순위로 둔다.

## 3. 후보 평가표

후보마다 다음 점수를 기록한다. 점수는 확인 전 임시값이 아니라, 검증자가 동일한 기준으로 채울 빈 칸으로 취급한다.

| 축 | 확인 질문 | 권장 통과 기준 |
|---|---|---|
| 중복 | 동일·유사 표기 계정, 앱, 서비스, 상표가 이미 있는가? | 동일 산업의 혼동 후보 0개, 유사 후보는 차별화 근거 기록 |
| 발음 | 한국어 화자가 한 번 듣고 재현하는가? 영어권에서 읽는 방식이 안정적인가? | 5명에게 1회 청취 후 철자 회수 80% 이상 |
| 철자/검색 | 들은 이름을 검색창에 정확히 입력할 수 있는가? | 대소문자·공백·하이픈 변형 3개 이내로 검색 가능 |
| 확장성 | 앱 외 웹, 뉴스레터, 콘텐츠, 상품에도 어색하지 않은가? | 특정 기능·지역·플랫폼을 이름이 강제하지 않음 |
| 기억성 | 10분 뒤 이름과 핵심 연상이 남는가? | 비보조 회상에서 5명 중 3명 이상 |
| 안전성 | 상표·저작물·유명 계정과 혼동 우려가 낮은가? | 검색 결과·국가·분류·확인 시각이 기록되고 법률 검토로 이관 |

총점으로 자동 확정하지 않는다. 중복 또는 상표 혼동 위험이 하나라도 높으면 다른 축의 고득점과 무관하게 `보류`한다.

## 4. 핸들 확인 절차 — 선점 없는 방식

핸들 확인은 공개 검색과 비상태변경 확인만 사용한다. 로그인 후 입력란에서 ‘사용 가능’ 여부를 확인하거나, 팔로우·예약·생성 버튼을 누르는 방식은 사용하지 않는다. 플랫폼이 검색을 제공하지 않거나 결과를 로그인 뒤에만 보여주면 `확인 불가`로 기록한다.

### 단계 A — 내부 중복·표기 정리

1. 후보의 정식 표시명, ASCII 표기, 발음, 금칙어·약어, 변형 핸들을 한 행에 고정한다.
2. 저장소와 기존 산출물에서 동일 문자열 및 유사 철자를 `rg`로 검색한다.
3. 기존 프로젝트·계정·도메인·문서와 충돌하면 외부 확인 전에 `내부 충돌`로 보류한다.

### 단계 B — 공개 웹 검색

1. 정확 일치(`"Waynote"`), 공백 제거(`waynote`), 음역·철자 변형, `app`, `brand`, `travel`, `choice` 조합을 각각 검색한다.
2. 검색 결과의 제목만 보지 말고 실제 공식 페이지, 앱 스토어 목록, 법인/상표 데이터베이스, 공개 프로필을 열어 소유자·업종·지역·최근 활동일을 기록한다.
3. 검색 결과가 없다는 사실은 가용성이나 권리 부재의 증거가 아니다. 결과 없음은 `미발견`으로만 기록한다.

### 단계 C — 플랫폼별 공개 확인

우선 대상은 Instagram, TikTok, YouTube, X, Threads, Facebook, LinkedIn, GitHub, 앱 스토어 검색, 공개 도메인 WHOIS/RDAP 결과다. 플랫폼의 공식 공개 검색 URL 또는 로그아웃 상태의 공개 페이지로 다음을 확인한다.

- 정확 핸들 및 점·하이픈·복수형 변형 존재 여부
- 동일 표시명인데 다른 핸들을 쓰는 계정이 있는지
- 계정이 비활성·삭제·잠금 상태여도 역사적 사용 흔적이 있는지
- 소개 문구·링크·콘텐츠가 같은 분야인지, 사칭·혼동 위험이 있는지

각 결과에는 `platform`, `query`, `observed_at(UTC)`, `result_url`, `status(occupied / not-found / inaccessible / ambiguous)`, `evidence_note`를 남긴다. `not-found`는 ‘사용 가능’으로 번역하지 않는다.

### 단계 D — 권리·확장 확인

1. 대상 국가의 상표 검색에서 동일·유사 표기를 상품/서비스 분류별로 검색한다.
2. 법인명·앱스토어·도메인·소셜 계정의 소유 주체가 일치하는지 대조한다.
3. 후보가 통과해도 상표 등록·법률 판단은 권리자 또는 전문가 승인 전까지 `미결`로 둔다.

## 5. 증거 기록 템플릿

```yaml
candidate: Waynote
display_name: Waynote
handle_variants: [waynote, way.note, waynote_app]
status: unverified
checked_at_utc: null
channels:
  - platform: Instagram
    query: waynote
    status: not-checked
    result_url: null
    evidence_note: null
pronunciation:
  ko: 웨이노트
  en: untested
duplicate_risk: untested
trademark_risk: untested
scalability_note: 이동 기록 외 뉴스레터·콘텐츠로 확장 가능한지 검토 필요
decision: hold
reason: 앱의 실제 범위와 권리 검색이 미확인
```

확인일이 지나면 결과를 최신 사실로 덮어쓰지 말고 새 행/새 기록을 추가한다. 핸들 상태는 변할 수 있으므로 최종 선택 시점에 재확인하되, 재확인 역시 선점 행위가 아니어야 한다.

## 6. 승인 게이트와 기각 기준

- `발견`: 이름·핸들 후보를 만든 상태. 사용 가능 주장 금지.
- `언어 통과`: 발음·청취 테스트에서 혼동이 낮은 상태.
- `중복 통과`: 공개 검색에서 혼동 후보를 검토하고 증거를 남긴 상태.
- `확장 통과`: 앱 외 채널과 제품 확장에 대한 설명이 가능한 상태.
- `권리 검토 대기`: 상표·법인·도메인 확인이 필요한 상태.
- `승인 대기`: 권리자/운영 책임자의 최종 결정 전 상태.

다음 중 하나면 후보를 기각 또는 보류한다: 유명 계정과 유사해 사칭으로 보일 가능성, 동일 업종의 선행 브랜드, 발음이 여러 방식으로 갈리는 조어, 앱 기능을 과도하게 고정하는 이름, 국가·언어 확장 시 부정적 의미, 검색 결과의 소유권이 불명확한 계정.

최종 승인 전에는 어떤 후보도 실제 계정으로 만들거나 핸들을 예약하지 않는다. 승인 후에도 먼저 사용 주체·권리 범위·플랫폼별 정책을 확인하고, 계정 생성은 별도 명시 승인과 기록이 있을 때만 진행한다.

## 7. Developer 인계

현재 구현 대상은 계정 생성기가 아니라 후보·증거 원장이다. 다음 역할/후속 작업은 `candidate registry → 비점유 검색 기록 → 발음 테스트 → 권리 검토 → 승인` 순으로 진행한다. 외부 상태를 바꾸는 API 호출, 핸들 예약, 로그인 기반 가용성 테스트는 이 작업 범위에 포함하지 않는다.
