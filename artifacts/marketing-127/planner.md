# marketing-127 Planner — 앱 카테고리 공백과 브랜드 Threads 역할 설계

## 문서 목적

현재 브랜드/앱을 공개적으로 운영하거나 이름을 확정하기 전에, 의사결정에 필요한 세 가지 정보의 부재를 명시한다.

1. 앱이 어느 카테고리에 속하는지 아직 확정되지 않았다.
2. 사용자가 반복해서 겪는 핵심 문제가 아직 한 문장으로 검증되지 않았다.
3. 첫 사용자가 누구인지, 어떤 상황에서 처음 가치를 느끼는지 실제 대화·사용 기록이 없다.

따라서 이번 산출물은 제품 포지셔닝이나 이름의 최종 승인서가 아니다. 공개 근거에서 출발해 내부 검증 순서, 브랜드 Threads 계정의 역할, 네이밍 판단 기준을 고정하는 Planner 문서다.

## 현재 확인된 사실과 공백

`artifacts/marketing-127/public-post-evidence-20260822.md`와 통합 전략에서 직접 확인된 사실은 `_archivenoh`의 2026-08-14·20·21 게시, 두 건의 무캡션 게시, 한 건의 “여행 계획에서 AI가 있어도 고르는 시간이 줄지 않았다”는 관찰형 캡션이다. 이 자료만으로는 앱이 여행 앱인지, 의사결정 앱인지, AI 도구인지, 기록 서비스인지 판정할 수 없다.

| 판단 항목 | 현재 상태 | 확정 전 필요한 증거 |
| --- | --- | --- |
| 앱 카테고리 | **미정**. 여행·의도적 소비·생활정보·업무 정리 등은 후보군일 뿐이다. | 한 문제를 반복 해결하는 실제 사용 흐름, 대체재, 문제 발생 빈도 |
| 핵심 문제 | **미정**. “AI가 있어도 선택 시간이 줄지 않는다”는 개인 관찰이지 시장 문제의 검증이 아니다. | 같은 상황을 겪은 사람의 구체적 사례, 현재 대안, 시간·비용·불안 등 손실 |
| 첫 사용자 | **미정**. 계정 독자나 팔로워를 첫 사용자로 간주하지 않는다. | 특정 상황·행동·접근 가능한 소규모 사용자 3~5명의 인터뷰 또는 비공개 사용 기록 |
| 가치 약속 | **보류**. “더 나은 선택”, “미니멀한 삶”, “AI로 해결” 같은 넓은 문구는 사용하지 않는다. | 첫 사용자가 결과를 자기 말로 설명하고 같은 흐름을 재사용하는 증거 |

`research-33`의 여행 준비·이동 운영, 생활정보 큐레이션, 의도적 소비, 소상공인 업무 정리 등은 내부 탐색 후보로만 계승한다. 후보 목록을 제품 카테고리나 브랜드 설명으로 옮기지 않는다.

## Planner의 현재 결정

### 1. 카테고리 결정은 문제와 사용자를 먼저 고정한 뒤 한다

카테고리는 기능 목록에서 고르지 않는다. 아래 문장을 실제 증거로 채울 수 있을 때만 임시 카테고리를 부여한다.

> `[특정 상황]의 [특정 사용자]가 [반복되는 문제] 때문에 [현재 대안의 비용]을 겪고 있으며, 이 앱으로 [관찰 가능한 결과]를 얻는다.`

위 문장의 주어·상황·문제·결과 중 하나라도 공란이면 공개 프로필이나 Threads 소개에서 카테고리를 단정하지 않는다. “AI 앱”, “생산성 앱”, “라이프스타일 앱”처럼 넓은 기술/분류어는 금지한다.

### 2. 핵심 문제는 기능이 아니라 손실과 반복으로 판정한다

다음 질문에 답이 없는 문제는 콘텐츠 소재이지 제품 문제로 승격하지 않는다.

- 언제 발생하는가?
- 사용자는 지금 무엇으로 버티는가?
- 얼마나 자주 반복되는가?
- 실패하면 무엇을 잃는가: 시간, 돈, 체력, 선택 확신, 작업 누락 중 무엇인가?
- 해결 후 무엇이 달라졌는지 제3자가 관찰할 수 있는가?

최소 판정 게이트는 서로 다른 3명 이상이 유사한 상황과 손실을 말하고, 그중 2명 이상이 같은 해결 흐름을 다시 사용하거나 먼저 요청하는 것이다. 이 기준 전에는 시장성·성장성·수익성을 주장하지 않는다.

### 3. 첫 사용자는 인구통계가 아니라 첫 장면으로 정의한다

“미니멀한 사람”, “AI에 관심 있는 사람”, “여행자”는 첫 사용자 정의로 불충분하다. 다음처럼 행동 장면으로 적는다.

> `[기간/상황] 안에 [결정 또는 정리 작업]을 해야 하고, 현재 [구체적 대안]을 쓰지만 [반복되는 마찰]을 겪는 사람.`

첫 사용자 후보를 고를 때는 접근 가능성, 문제의 최근성, 직접 말할 수 있는 손실, 개인정보 없이 관찰 가능한 행동, 1회 안에 확인 가능한 결과를 본다. 공개 모집·광고·대량 DM은 이번 범위에 포함하지 않는다.

## 브랜드 Threads 계정의 역할

브랜드 Threads 계정은 제품을 이미 정의한 회사의 방송 채널이 아니라, **문제 언어와 관찰 가능한 선택을 축적하는 공개 브랜드 표면**으로 둔다.

### 해야 할 일

- 실제 장면에서 발견한 선택의 마찰을 짧게 기록한다.
- 하나의 게시물에 한 상황·한 관찰·한 열린 다음 질문만 둔다.
- 기능보다 사용자의 말, 현재 대안, 문제를 미룬 이유를 모은다.
- 계정의 반복 어휘가 카테고리 후보와 충돌하는지 관찰한다.
- 제품을 만들기 전에는 “우리가 무엇을 해결한다”보다 “어떤 문제를 계속 보고 있는가”를 보여준다.

### 하지 않을 일

- 미정인 앱 카테고리·타깃·효과를 프로필이나 게시물에서 확정적으로 선언하지 않는다.
- 존재하지 않는 사용 후기, 고객 수, 전환, 해결률을 만들지 않는다.
- Threads 반응을 수요 검증으로 과대해석하지 않는다. 좋아요·팔로워보다 구체적인 자기 사례, 대체재 언급, 다시 겪는 상황의 설명을 본다.
- 제품 출시, 가입 유도, 링크 확산, 광고, DM 자동화, 댓글 대량 활동을 수행하지 않는다.

### 내부 측정표

게시 전 초안 단계에서 다음 열만 기록한다: 원본 장면, 문제 가설, 독자가 사용한 표현, 현재 대안, 다음에 확인할 질문, 근거 상태. 공개된 반응이 생기더라도 반응 수가 아니라 반복되는 문제 표현과 자발적 사용 맥락을 질적으로 기록한다. 실제 게시·프로필 변경은 사용자 명시 승인이 있는 별도 작업이다.

## 네이밍 판단 기준

이름은 먼저 고르지 않고, 카테고리·핵심 문제·첫 사용자 문장이 채워진 뒤 평가한다. 후보마다 아래 점수를 내부적으로 기록하되, 점수만으로 승인하지 않는다.

| 기준 | 통과 질문 | 탈락 신호 |
| --- | --- | --- |
| 문제 연결성 | 이름을 본 첫 사용자가 해결하려는 장면을 잘못 상상하지 않는가? | AI·생산성·힐링 등 추상 약속만 남음 |
| 확장 여지 | 첫 문제를 담되 검증 후 인접한 흐름으로 확장 가능한가? | 한 기능·한 유행어·한 채널에 고정됨 |
| 발음·기억 | 한국어로 한 번 듣고 말할 수 있고 철자를 재현할 수 있는가? | 발음이 여러 개이거나 검색 철자가 불명확함 |
| 구별성 | 경쟁 카테고리의 일반 명사와 혼동되지 않는가? | `AI`, `smart`, `life`, `flow` 조합처럼 범용적임 |
| 정서 적합성 | `_archivenoh`에서 관찰된 낮은 온도·선택 중심 톤과 맞는가? | 과장, 속도, 만능 해결, 전문가 권위의 뉘앙스 |
| 신뢰·안전 | 이름이 의료·금융·법률 보증이나 자동결정을 암시하지 않는가? | “보장”, “완벽”, “대신 결정”을 연상시킴 |
| 채널 적합성 | Threads에서 문장 속에 자연스럽게 넣고 설명할 수 있는가? | 이름 자체를 매번 길게 해설해야 함 |
| 운영 가능성 | 상표·도메인·스토어·소셜 핸들 충돌을 확인할 수 있는가? | 권리·검색·계정 사용 가능성이 불명확함 |

최종 후보는 문제 문장과 첫 사용자 장면에 대해 오해가 가장 적고, 한 문장으로 설명 가능한 1~2개만 남긴다. 권리·핸들·도메인 확인 전에는 예약·등록·프로필 변경을 하지 않는다.

## 다음 내부 검증 순서

1. 후보 문제 3개를 각각 `상황 → 현재 대안 → 손실 → 원하는 결과`로 한 줄씩 작성한다.
2. 각 문제에 맞는 첫 사용자 장면을 하나씩 쓰고, 접근 가능한 비공개 검증 대상이 있는지 확인한다.
3. Threads용 관찰 초안은 브랜드 소개가 아니라 문제 언어 수집용으로 3개 만든다.
4. 비공개 대화/사용 기록에서 같은 표현과 재사용 행동이 나오는지 확인한다.
5. 하나의 문제와 첫 사용자만 임시 카테고리로 명명하고, 그 뒤에 이름 후보를 평가한다.
6. Red 검토에서 사실·가설·추정, 계정 역할, 공개 행동 금지, 이름의 과장성을 확인한다.

## 완료 조건과 경계

완료로 보려면 카테고리 1개, 핵심 문제 1개, 첫 사용자 장면 1개가 각각 근거와 함께 채워지고, Threads 계정의 역할과 네이밍 게이트가 다른 작업자가 재사용할 수 있어야 한다. 현재는 이 조건을 충족하지 못했으므로 상태는 `DRAFT / CATEGORY-USER-PROBLEM-UNKNOWN`이다.

이번 작업은 내부 Planner 문서 작성만 수행한다. 공개 게시, Threads 계정 생성·접속·변경, 프로필 수정, 외부 메시지, 광고, 가입·결제, 이름 예약·등록은 실행하지 않는다.
