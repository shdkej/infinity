# marketing-127 Operator — Threads 계정명 최종 결정안

## 운영 경계

- 목적: 앱 전담 브랜드 Threads 계정명 후보를 안전하게 좁히고, 사용자가 최종 선택할 수 있는 결정안을 남긴다.
- 현재 상태: **HOLD — 앱의 핵심 문제와 첫 사용자가 확인되기 전에는 이름을 확정하지 않는다.**
- 이 문서에서 수행하지 않은 일: 핸들 중복 조회, 상표 검색, 계정 생성·핸들 선점, 프로필 변경, 게시·예약, 외부 발송.
- 위 검증은 후보와 대상 국가·상품류가 정해지고 사용자가 별도 승인한 뒤에만 수행한다. 확인 전에는 `가능`이나 `사용 가능`으로 표현하지 않는다.

## 1. 최종 결정안 템플릿

아래 블록을 후보 검토 때 복사해 채운다.

```markdown
### 최종 결정안 — [날짜/버전]

- 앱/제품:
- 계정 역할 한 문장:
- 핵심 문제:
- 첫 사용자:
- 운영 언어/시장:
- 원하는 인상: [예: 차분함 / 실용성 / 실험성]
- 금지할 연상·단어:

#### 추천

- 1순위 이름:
- 표시명:
- 핸들 후보:
- 한 줄 이유:
- 이 이름이 약속하는 범위:
- 아직 확인하지 않은 위험:

#### 백업

| 순위 | 이름/핸들 | 채택 조건 | 포기 조건 |
|---|---|---|---|
| 2 |  |  |  |
| 3 |  |  |  |

#### 결정

- 상태: [CONTINUE / HOLD / CHANGE]
- 선택권자:
- 선택 마감 또는 다음 확인 시점:
- 선택 후 순서: 중복·상표 재확인 → 사용자 승인 → 계정 생성/변경 여부 결정
- 외부 상태 변경 승인: [미승인 / 승인]
- 근거 문서:
```

### 결정 규칙

- `CONTINUE`: 추천 1개와 백업 2개가 있고, 세 후보 모두 검증 체크리스트를 통과하거나 미확인 항목이 명시되어 있다.
- `HOLD`: 앱의 핵심 문제·첫 사용자·시장 중 하나가 없어 이름의 의미를 과도하게 단정하게 된다.
- `CHANGE`: 중복, 상표 위험, 발음·표기 혼란, 또는 향후 앱 확장을 막는 결함이 발견된다.
- 후보가 좋아 보여도 핸들 선점이나 계정 생성은 결정 완료의 일부로 간주하지 않는다. 별도 승인 전에는 제안 상태로만 둔다.

## 2. 후보 검증 체크리스트

각 후보마다 사실·판단·미확인을 분리해 기록한다.

### A. 중복·식별성

- [ ] Threads 표시명과 핸들 표기를 분리해 적었다.
- [ ] 대소문자, 숫자, 밑줄, 철자 변형을 포함한 유사 후보를 함께 적었다.
- [ ] Threads에서 동일·유사 핸들이 있는지 확인할 대상과 확인 시각을 기록했다.
- [ ] Instagram, X, 도메인 등 다른 채널의 동일·유사 표기를 별도 확인 대상으로 남겼다.
- [ ] 검색 결과가 없다는 이유만으로 “사용 가능”이라고 결론 내리지 않았다.
- [ ] 혼동 가능성이 있는 발음·철자·번역·약어를 기록했다.

권장 기록 형식:

| 후보 | 확인 대상/변형 | 결과 | 확인 시각 | 증거 또는 미확인 사유 |
|---|---|---|---|---|
|  |  | 미확인/충돌 없음/유사 충돌 |  |  |

### B. 상표·법적 위험

- [ ] 운영할 국가 또는 시장을 확인했다.
- [ ] 앱의 상품·서비스 범위를 한 문장으로 고정했다.
- [ ] 동일·유사 표장의 검색 대상, 관할, 상품류, 확인 시각을 기록했다.
- [ ] 유명 브랜드·제품명·서비스명과 혼동될 표현이 없는지 검토했다.
- [ ] 일반명사·설명적 단어만으로 이루어진 이름의 식별력 한계를 적었다.
- [ ] 결과를 법률 자문이나 등록 가능성 보장으로 표현하지 않았다.
- [ ] 의심 후보는 점수와 무관하게 `CHANGE` 또는 법률 검토 대기로 처리했다.

권장 상태: `미조회` / `추가 검토 필요` / `명확한 충돌 없음(법적 보장 아님)` / `사용 중단`.

### C. 확장성·운영성

- [ ] 현재 앱 기능 하나에만 갇히지 않고 인접 기능으로 확장 가능한가?
- [ ] 특정 플랫폼, 기능 버전, 지역, 유행어를 이름에 불필요하게 고정하지 않는가?
- [ ] 1년 뒤 앱이 바뀌어도 계정 역할 한 문장과 어긋나지 않는가?
- [ ] 한국어 화자가 읽고 말하기 쉬운가?
- [ ] 영어권 또는 목표 시장에서 발음·철자·부정적 의미 문제가 없는가?
- [ ] Threads의 표시명 길이와 핸들 제약 안에서 일관되게 쓸 수 있는가?
- [ ] 소개 문구, 시리즈명, 해시태그, 앱 기능명으로 파생하기 쉬운가?
- [ ] 운영자가 매번 이름의 뜻을 설명하지 않아도 콘텐츠 주제가 연결되는가?

### D. 결정용 점수(보조 지표)

점수는 검증 실패를 상쇄하지 않는다. `상표 위험`, `중복 충돌`, `확장성 치명적 결함`은 즉시 탈락 사유다.

## 3. 사용자에게 물을 최소 추가 질문

다음 세 가지만 답해주면 후보를 의미 있게 좁힐 수 있다.

1. **앱이 해결하는 핵심 문제를 한 문장으로 말하면 무엇인가요?** (아직 개발 전이면 가장 먼저 검증하려는 문제도 괜찮습니다.)
2. **첫 사용자는 누구인가요?** (예: 혼자 일하는 사람, 여행자, 개발자처럼 가장 좁은 표현 하나면 됩니다.)
3. **이름의 언어·톤은 어느 쪽을 원하나요?** `한국어 / 영어 / 혼합` 중 하나와 `차분한 기록형 / 실용적인 도구형 / 실험적인 스튜디오형` 중 하나를 골라주세요.

답을 받기 전에는 후보의 의미를 임의로 보강하거나, 중복·상표 결과를 추정해 결정을 진행하지 않는다.

## 4. 인계 및 승인 경계

- 다음 담당: 후보 생성·비교 담당자가 10개 이상 후보와 상위 3개를 위 표 형식으로 채운다.
- Operator 확인: 후보별 중복·상표·확장성의 확인 범위와 미확인 항목을 검수한다.
- 사용자 결정: 추천 1개/백업 2개 중 하나를 선택한다.
- 별도 승인 없이는 외부 조회, 핸들 선점, 계정 생성·변경, 게시, 예약, 발송을 하지 않는다.
