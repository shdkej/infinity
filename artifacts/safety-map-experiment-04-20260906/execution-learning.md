## 관찰

1. 30분 상한과 cycle의 Red·마감 분리는 정착했다.
2. T3~T12의 대부분은 데이터 계약·필터·검토 규칙을 만든 cycle이었다. 이들은 안전 경계에는 기여했지만, 표시 가능한 지역 데이터나 사용자 흐름을 만들지 않았다.
3. UI 변경은 T13 이후에 집중됐다. 사용자 피드백에 따른 표시·검색 수정은 계획된 acceptance criteria가 아니라 사후 수정이었다.
4. `48개 중 16개 완료`라는 타임라인 헤더는 parent 완료 수와 leaf 총수를 섞은 집계 오류다. 실제 task JSON은 48/48 done이다.

## 다음 작업의 측정 규칙

각 parent cycle은 아래 중 하나를 evidence로 남긴다.

- `user_visible_delta`: 사용자가 실제 화면에서 확인할 변화와 Red 렌더 증거
- `reusable_rejection`: 후보 URL·날짜·공간 단위·탈락 사유가 있는 재사용 가능한 기각 근거

둘 다 없으면 `done`이 아니라 `rework`이다. 모든 leaf는 `started_at`, `completed_at`, `active_min`, `rework_intervals`, `waiting_intervals`를 남긴다. 다음 유사 작업 3건부터는 누락 시간을 제외한 active+rework 중앙값으로 예산을 갱신한다.
