# Virtue 첫 세션 제품 본체/범퍼 경계표

> PLG(Product-Led Growth) 온보딩 렌즈로 Virtue 첫 세션을 **제품 본체(Product Body)**와 **범퍼(Bumper)**로 분리하는 기준표.
> prelaunch 첫 10~20명 관찰에서 "설명 부족(범퍼 문제)"과 "제품 약속/결과 불일치(본체 문제)"를 구분해 읽기 위한 내부 판독 도구.
> 기존 first value 매핑과 선행 문서를 재정의하지 않는다.

## §1 PLG 본체/범퍼 개념

**제품 본체(Product Body)**: 사용자가 제품의 핵심 경험을 직접 완수해 첫 가치에 도달하는 경로. 투어나 외부 설명 없이도 제품 자체가 사용자를 첫 가치까지 이끄는 부분. 예: Virtue에서 `/add`에 사진을 올리면 AI가 판정하고 `deed_judged`/`deed_saved`가 발화하는 흐름 자체.

**범퍼(Bumper)**: 사용자가 본체 경로에서 이탈하거나 막힐 때 개입하는 최소 보조 장치. 빈 상태 CTA, 툴팁, 인라인 힌트, 단계 안내 등이 해당한다.

**구분 원칙**:
1. 본체가 작동하면 범퍼는 필요 없다.
2. 범퍼는 이탈 지점에만 배치한다. 시작부터 투어로 채우는 것은 본체가 약하다는 신호다.
3. prelaunch 판독에서: 사용자가 "어디서 막혔나"는 본체 문제, "어디서 길을 잃었나"는 범퍼 문제로 분류한다.

## §2 Virtue 첫 세션 표면 정의 (S1~S5)

| 표면 ID | 표면 | 핵심 이벤트 | 비고 |
|---------|------|------------|------|
| S1 | `/` 홈 | — | 첫 약속/의도 형성 |
| S2 | `/add` 입력 | `add_flow_started`(72) | 의도 시작 |
| S3 | `/add` 결과 카드 | `deed_judged`(106) | AI 판정 |

## §3 심장 표: J1~J4 × 표면 × 본체/범퍼 역할 × 판독 기준

### J1 기록형 (first value: `deed_saved`)

| 표면 | 본체 역할 | 범퍼 역할 | 정상 종료 판독 | 막힘 판독 |
|------|-----------|-----------|----------------|----------|
| S1 `/` | 오늘 덕행 기록 CTA + 최근 덕행 카드 | 빈 상태 안내 (첫 방문 시) | add_flow_started 진입 | S1 이탈 = 본체 기록 약속 불명확 |
| S2 입력 | 사진+메모 입력 UX (이미 얇음) | 없음 | S3 진입 | 입력 보류/이탈 = 입력 부담 |
| S3 결과카드 | 판정 결과 확인 (기록 가치 확인) | 저장 유도 CTA (경미) | S4 이동 | S3 후 저장 없이 이탈 = 저장 막힘 |
| S4 저장 | `deed_saved` 발화 = J1 첫 가치 | 없음 | deed_saved 발화 | deed_saved 미발화 |
| S5 복귀 | 저장된 덕행 카드 표시 | 없음 | 홈에서 기록 확인 | — |

- **정상 종료**: S4 `deed_saved` 발화
- 막힘 1순위: S1→S2 미진입 (본체 기록 약속 불명확)
- 막힘 2순위: S3 후 S4 미이동 (저장 범퍼 부재 or 본체 저장 단계 문제)

### J2 누적형 (first value: `deed_saved`, 반복 누적 필요)

| 표면 | 본체 역할 | 범퍼 역할 | 정상 종료 판독 | 막힘 판독 |
|------|-----------|-----------|----------------|----------|
| S1 `/` | 최근 덕행 누적 표시 + 진화 신호 | 누적 payoff 설명 (첫 방문 — J2 앞단 약함 위험) | add_flow_started 진입 | S1 이탈 = 누적 약속 불명확 |
| S2 입력 | 기록 입력 UX | 없음 | S3 진입 | 입력 이탈 |
| S3 결과카드 | 판정 카드 | 없음 | S4 이동 | S3 후 이탈 |
| S4 저장 | `deed_saved` 발화 = J2 첫 가치 시작 | 없음 | deed_saved 발화 | deed_saved 미발화 |
| S5 복귀 | **`level_up_viewed`(199) 조건부 = 누적 payoff 본체** | 누적 payoff 시각화 (범퍼 역할 겸) | level_up_viewed or 누적 카드 확인 | 누적 payoff 못 알아챔 = F8 마찰 (three-screen §3-B 뒷단 누출) |

- **정상 종료**: S4 `deed_saved` + S5 누적 payoff 인식
- 막힘 1순위: S5 누적 payoff 미인식 (three-screen §3-B 뒷단 누출, F8)
- 막힘 2순위: S1→S2 미진입 (누적 약속 불명확)

### J3 AI 호기심형 (first value: `deed_judged`, 저장 불필요)

| 표면 | 본체 역할 | 범퍼 역할 | 정상 종료 판독 | 막힘 판독 |
|------|-----------|-----------|----------------|----------|
| S1 `/` | **없음 (J3 AI 판정 약속 부재 = 본체 공백)** | J3 앞단 진입 힌트 (현재 부재 — F7 마찰) | add_flow_started 진입 | **S1 이탈 = J3 앞단 끊김 (본체 공백, three-screen §3-A)** |
| S2 입력 | 사진+메모 + AI 판정 대기 | 없음 | S3 결과카드 | 입력 이탈 |
| S3 결과카드 | **`deed_judged` 발화 = J3 first value** | 없음 (결과카드가 본체 완결) | deed_judged 발화 후 저장 없이 닫음 = **정상** | deed_judged 미발화 |
| S4 저장 | 선택적 — 저장하지 않는 것이 J3 정상 | 없음 | 저장 없이 닫음 = 정상 종료 | 저장 없이 이탈을 이탈로 오독 (**misread 금지**) |
| S5 복귀 | 해당 없음 | 해당 없음 | — | — |

- **정상 종료: `deed_judged` 발화 후 저장 없이 닫음 (J3 자연 종료)**
- **막힘 1순위: S1 이탈 = J3가 `/`에서 AI 판정 약속을 못 알아챔 (three-screen §3-A 앞단 끊김, F7)**
- **오독 금지**: `deed_judged`−`deed_saved` 갭(저장 없음)을 J3에서 이탈로 읽지 않는다.

| S4 저장 | `deed_saved` 발화 = J4 첫 가치 | 없음 | deed_saved 발화 | deed_saved 미발화 |
| S5 복귀 | 회고 기록 카드 확인 | 없음 | 홈에서 회고 기록 확인 | — |

- **정상 종료**: S4 `deed_saved` 발화
- 막힘 1순위: S1→S2 미진입 (회고 약속 불명확)

## §4 본체 강화 vs 범퍼 배치 판단 기준

prelaunch 첫 10~20명 관찰 신호 판독:

| 관찰 신호 | 판독 | 우선 조치 방향 |
|-----------|------|----------------|
| S1에서 `/add` 진입 안 함 | 본체 약속 불명확 | 본체 강화 (홈 화면 약속 개선) — 범퍼 아님 |
| `/add` 들어와서 입력 보류 | 입력 부담 or 의미 모름 | 본체 입력 UX 점검 or 최소 범퍼 힌트 |
| 결과카드 후 저장 없이 닫음 (J3) | **정상 종료** | 아무 조치 없음 — 오독 주의 |
| 결과카드 후 저장 없이 닫음 (J1/J2/J4) | 저장 단계 막힘 | 범퍼: 저장 유도 CTA (경미) |
| 저장했지만 S5 복귀 후 재방문 없음 | J2 뒷단 누출 | 본체 강화: 누적 payoff 가시화 |
| J3 진입 자체 안 함 | J3 앞단 끊김 | **본체 강화: `/` AI 약속 추가 — 범퍼 아님** |

## §5 prelaunch 금지선

- 본체/범퍼 분류를 전환율, 이탈률, PMF 결론, 합격선으로 환산하지 않는다.
- 1~2명의 신호로 본체 약함/강함을 단정하지 않는다.
- J3 `deed_judged` 후 저장 없음 = 이탈로 읽지 않는다 (J3 정상 종료).
- `deed_save_capped`(167)을 범퍼 배치 또는 저장 경로 수정 근거로 쓰지 않는다 (availability/friction 신호).
- 본체/범퍼 조치 후보는 prelaunch 반복 신호가 있을 때 proposal-only로 분리한다.
- 새 이벤트, 속성, 코드, 카피, 계측, dashboard, session replay, 배포, 외부 발송, 비용, 시크릿, 권한, 개인정보 변경 금지.
