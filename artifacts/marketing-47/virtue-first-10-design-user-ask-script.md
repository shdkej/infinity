## 0. 선행 산출물과의 위치 (충돌 없음)

이 스크립트는 새 층을 *추가*할 뿐 기존 문서를 재정의하지 않는다.

| 선행 산출물 | 그 문서의 층 | 이 스크립트의 관계 |
|---|---|---|
| `first-real-user-baseline-template` | 사용자별 **기록표** | §D 자기 말 기록 칸이 이 기록표로 흘러든다(수기만, 신규 계측 0). |
| `first-60-second-value-observation-script` | 세션 **중** 손기록 관찰 | §C-1(첫 가치 위치)은 관찰 직후의 **언어 확인** 층. 관찰=세션 중, ask=세션 후. |
| `ai-promise-decision-control-audit-table` (m45) | 카피의 **동사 프레임** 감사 | §A 초대 문장은 m45 프레임(판결 아닌 관점)을 따르고, §C-3은 그 프레임의 *사용자 인지*를 묻는 질문이다. 카피 변경 0. |

## A. 잡별 초대 문장 후보 (proposal-only, 내부)

> 동사 프레임 규칙(m45): "본 / 읽어주는 / 보여주는 / 남는 / 쌓이는"(관점·기록) 사용, "채점 / 판정받는 / 평가받는"(판결) 회피.
> 각 잡의 first value를 초대 문장이 미리 가리키게 한다.

### J1 기록형 — first value `deed_saved`
- "오늘 한 일 하나, 그냥 적어두면 남는 거 써볼래요? 평가받는 게 아니라 기록이 쌓이는 쪽이에요."
- "오늘 뭐 했는지 한 줄 남겨두는 앱인데, 10분만 써보고 어땠는지 말해줄 수 있어요?"

### J2 누적형 — first value `deed_saved` (누적의 시작점)
- "며칠 적어두면 그게 쌓여서 보이는 게 있는 앱이에요. 첫날 한 번 써보고 느낌 들려줄래요?"
- "한 일이 모여서 점점 쌓이는 걸 보는 쪽인데, 한번 써보고 쌓이는 맛이 있는지 말해줄래요?"

### J3 AI 호기심형 — first value `deed_judged` (결과 카드 도착 자체가 가치)
- "오늘 한 일을 AI가 어떻게 읽어주는지 한번 볼래요? 점수 받으러 가는 게 아니라, AI가 정리해서 보여주는 걸 보는 거예요."
- "내가 한 일을 AI한테 보여주면 어떻게 읽는지 궁금하면 한번 써보고, 그 화면 보고 든 생각만 말해줄래요?"
- ⚠️ J3는 결과 카드를 본 뒤 저장 없이 닫아도 정상이다. 초대 문장에 "저장해야 끝"이라는 뉘앙스를 넣지 않는다.

### J4 회고형 — first value `deed_saved` (회고 재료로 남는 것)
- "요즘 어떻게 지냈는지 돌아보는 용도로 한번 써볼래요? 한 일을 적어두면 나중에 돌아볼 거리가 돼요."
- "지난 며칠을 돌아보고 싶을 때 쓰는 쪽인데, 한 번 적어보고 돌아볼 만한지 말해줄 수 있어요?"

> 어떤 잡으로 올지 모를 때는 J1(가장 중립적)으로 초대하고, §B-2 답에서 실제 잡 신호를 읽는다.

## B. 사용 전 2문항 (세션 시작 전)

1. **현재 행동 / 대체재** — "요즘 하루(또는 한 주)를 돌아보거나 한 일을 정리하는 거, 지금은 뭘로 어떻게 하고 있어요?"
   - 읽는 것: 현재 문제 언어, 대체재, 안 하고 있다면 그 이유.
2. **잡 신호 / 기대** — "지금 이걸 한번 써보려는 이유가 뭐예요? 뭘 기대하고 들어왔어요?"
   - 읽는 것: 어떤 잡(J1~J4)으로 들어오는가, 기대한 가치.

## C. 첫 세션 후 4문항 (세션 직후)

1. **첫 가치 위치** — "방금 써본 것 중에 '어, 이거네' 싶은 순간이 있었어요? 있었다면 정확히 어디서였어요?"
   - 읽는 것: first value 도달 여부와 위치. 잡별로 다르다 — J3는 결과 카드(`deed_judged`), J1·J2·J4는 저장 후(`deed_saved`).
2. **부담 / 마찰** — "쓰는 동안 부담스럽거나 멈칫하거나 '이거 왜 이래?' 한 데가 있었어요?"
   - 읽는 것: friction/부담 신호. 단, 저장 상한·503·지연(`deed_save_capped`)은 **availability/friction**으로 분류하고 가치 부재로 읽지 않는다.
3. **결정-위임 인지** (AI 결과 화면을 본 경우, J3 핵심) — "방금 AI가 보여준 게 '당신 대신 정해준 것' 같았어요, 아니면 '당신이 보라고 정리해준 것' 같았어요? 왜 그렇게 느꼈어요?"
   - 읽는 것: 사용자가 출력을 *판결(정체성 사실)*로 읽는가 *조언(마지막 선택 내 것)*으로 읽는가(m45/m38). 결론이 아니라 인지 신호.
4. **다음 행동 명료성** — "저장하거나 판단을 본 바로 다음에, 이제 뭘 하면 될지 한 문장으로 바로 말할 수 있었어요? 뭐라고 느꼈어요?"
   - 읽는 것: first value 직후 `time-to-next-value`가 이어졌는지. J1·J2·J4는 저장 뒤 홈/최근 덕행 기준의 다음 행동 언어를, J3는 결과 카드 뒤 `여기서 멈춰도 됨 / 더 해볼 수 있음` 선택 언어를 읽는다.

## E. 운영 규칙 (어떻게 읽나)

- **언어 우선, 비율 금지.** 첫 10명은 방향 재료다. activation rate·PMF·전환율·retention%로 환산하지 않는다(Prelaunch Decision Boundary).
- **도움의 목표 = 자기 말로 말하게 하기.** 성찰형 제품에서 첫 사용자 도움은 사용자의 판단·선택·성찰을 *대신*하지 않는다. 도움이 성찰을 대행하면 수집하려던 자기 말 자체가 사라진다(출처노트·m46).
- **first value는 잡별로.** J1·J2·J4=`deed_saved`, J3=`deed_judged`.
- **J3 정상 종료.** 결과 카드 후 저장 없이 닫음은 정상이다. 저장 넛지를 띄우지 않고, 실패로 읽지 않는다(judged−saved 갭=정상).
- **다음 행동 질문은 강요하지 않는다.** J1·J2·J4에서는 저장 뒤 다음 한 걸음이 자기 말로 나오는지 보고, J3에서는 저장 계획이 아니라 `멈춤/재판정/실행` 중 무엇이 자연스러웠는지 듣는다.
- **트래픽 먼저 분리.** maker self-test/synthetic/mock은 제외·표시하고 사람 실사용과 섞지 않는다.
- **가용성≠가치.** `deed_save_capped`·503·지연은 availability/friction이지 value·upgrade demand가 아니다.

## G. 가정·충돌·학습 분리

### 계승한 가정 (inherited)
- first value 매핑: J1·J2·J4=`deed_saved`, J3=`deed_judged` (m06 First Value Mapping) — 재정의 0.
- 작은 표본은 방향 재료, decision-grade 아님 (Prelaunch Decision Boundary).
- `deed_save_capped`·503·지연 = availability/friction, value 아님 (Availability And Friction Are Not Value).
- 사용자 언어는 증거이지 결정 자체가 아니다 (m27 Message Confusion As Evidence).
- 비자율 AI라 위험은 행동적 해가 아니라 자기인식 오보정, 결정-위임 위험은 동사 프레임에 실림 (m38·m45).
- 성찰·선택이 본체인 경험형 제품에서 do-for-you는 제품 의미를 소거한다 (m46).

- **없음.** 기존 경계를 바꾸지 않고 "초대·질문·기록"이라는 첫 사용자 수집 루프 층만 추가한다.
