# Virtue 홈 J1/J3 2갈래 시작선 — 검증 질문 1장

> 이 문서는 J1/J3 2갈래 시작선 안(B안)을 홈 첫 화면에 반영하기 전에
> "첫 화면만 보고 자기 길을 말할 수 있는가"를 판정하기 위한 검증 질문지다.
>
> 배경: `marketing-99`에서 B안이 prelaunch 다음 비교 후보로 선정됨.
> UI 반영/카피 확정/배치 배포는 이 판정 이후 별도 approval intent로 분리한다.

---

## 1. 이 안이 말하는 것

J1/J3 2갈래 시작선이란:
- **홈 첫 화면에서 두 가지 길을 명시적으로 제시**하는 구조
- J1(기록형): 오늘 있었던 일을 기록하고 AI가 덕행을 판정해주는 길 → first value = `deed_saved`
- J3(AI 호기심형): AI가 내 행동을 어떻게 판정할지 궁금해서 바로 넣어보는 길 → first value = `deed_judged`

현재 홈은 단일 CTA(J1 중심)이며, J3 약속은 `/add` 안에서야 분명해진다.

---

## 2. 첫 문장 후보

홈 헤드라인은 분기 전 공통 한 줄이어야 한다. 아래 중 하나:

| 후보 | 동사 프레임 | 주의 |
|------|-------------|------|
| A. "오늘 있었던 일, AI가 같이 봐줄게요." | 관점(같이 봄) | ✅ 판결 동사 없음 |
| B. "오늘 하루를 기록하거나, AI에게 물어보세요." | 행동 안내형 | 분기를 직접 예고함 |
| C. "오늘 기억하고 싶은 일이 있나요?" | 기존 (J1 중심) | J3 약속이 없음 |

**판정 기준**: 이 문장을 읽은 J3 사용자가 "나도 여기서 뭔가 할 수 있겠다"고 느끼는가?

---

## 3. 버튼 문구 후보

두 버튼이 나란히 나타날 때:

**J1용 버튼**
- "오늘 기억 남기기" ← 권장 (관점 동사, 저장 중심)
- "덕행 기록하기" ← 대안
- ❌ "AI 채점받기" ← 판결 동사, 금지

**J3용 버튼**
- "AI가 어떻게 볼지 물어보기" ← 권장 (호기심 + 관점 동사)
- "내 선택 AI에게 보여주기" ← 대안
- ❌ "AI가 판정해주기" ← 판결 동사, 금지

**공통 규칙**: 두 버튼 모두 사용자가 원하는 결과를 AI에게 알려주는 프레임으로 쓴다. (→ MARKETING_LEARNINGS: Decision-Delegation Risk Rides The Verb)

---

## 4. 판정 질문

이 안을 실제로 채택할지 결정할 때 아래 질문을 순서대로 확인한다.

### Q1. 목적 신호 선명도
> **"첫 화면만 보고 J1 사용자는 자기 길을 즉시 말할 수 있는가?"**
> **"첫 화면만 보고 J3 사용자는 자기 길을 즉시 말할 수 있는가?"**

- ✅ 채택 조건: 두 질문 모두 "예" (망설임 없이 바로 선택 가능)
- ❌ 보류 신호: 한 쪽이라도 "두 버튼이 어떻게 다른가요?"라고 되묻거나 5초 이상 고민

### Q2. 동사 프레임 점검
> **"두 버튼 모두 판결 동사(채점, 판정)를 피하고 관점 동사(봄, 보여줌, 물어봄)를 쓰는가?"**

- ✅ 채택 조건: 두 버튼 모두 관점 동사
- ❌ 보류 신호: 어느 한 버튼에라도 AI를 결정자로 세우는 동사가 들어감

### Q3. J2/J4 배제 없음 확인
> **"누적형(J2)·회고형(J4) 사용자가 어느 버튼도 아니라고 느끼지 않는가?"**

- ✅ 채택 조건: J2/J4도 J1 버튼("기억 남기기")으로 자연스럽게 흐를 수 있음
- ❌ 보류 신호: J2/J4 사용자가 "나는 어디에 속하지?"라는 혼란을 보임

### Q4. 분기 피로 없음 확인
> **"두 버튼을 보고 어느 쪽을 눌러야 할지 바로 결정하는가, 아니면 설명을 읽으러 머무는가?"**

- ✅ 채택 조건: 설명 없이 바로 한 버튼을 선택
- ❌ 보류 신호: 두 버튼의 차이를 설명하는 텍스트를 찾거나 토글/탭을 기대함

## 5. 보류 조건

아래 중 하나라도 해당하면 B안을 채택하지 않고 A안(단일 CTA 유지) 또는 추가 조사로 돌아간다.

1. **분기 혼란**: Q1/Q4에서 2명 중 1명 이상이 버튼 의미를 묻거나 5초 이상 머뭄
2. **판결 동사 오염**: 버튼 문구를 정할 때 관점 동사로 쓰기가 구조적으로 어려운 경우
3. **J2/J4 이탈**: J2/J4 사용자가 두 버튼 모두 "내 것이 아니다"라고 느끼는 경우
4. **prelaunch 적합성**: 첫 10명 초대 단계에서 A/B 분기 자체를 관리하기 어려운 경우
5. **J1 버튼이 기존 단일 CTA보다 약해진 경우**: J1 사용자가 단일 CTA일 때보다 더 오래 고민하는 신호

## 6. C안(샘플 결과 preview)과의 차이

| 비교 축 | B안 — J1/J3 2갈래 시작선 | C안 — 샘플 결과 preview |
|---------|--------------------------|-------------------------|
| 전달 방식 | 의도로 분기 ("나는 어떤 길?") | 증거로 끌어당김 ("이런 결과가 나와") |
| 주요 설득 대상 | 목적이 두 가지로 나뉜 사용자 | 결과가 어떤지 궁금한 사용자 |
| J3 적합성 | 명시적으로 J3를 부름 | J3를 간접 설득 (결과 카드 예시로) |
| 위험 | 분기 혼란, J2/J4 배제 | 대표성 오해, 과한 약속 |
| prelaunch 실험 난이도 | 버튼 2개 배치 변경 필요 | 샘플 데이터 준비 필요 |
| 실패 판정 기준 | Q1/Q4 보류 신호 발생 시 | "나는 이런 결과 안 나올 것 같다" 반응 |

**핵심 차이**: B안은 "나는 어디에 속하는가"를, C안은 "이게 뭘 해주는 서비스인가"를 첫 화면에서 답한다. 두 질문은 독립적이므로 하나가 맞아도 다른 하나는 틀릴 수 있다.
