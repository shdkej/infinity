# T3.1 — 승인 전 14일 최소 검증 프로토콜

- 작성 시각: 2026-09-10T15:16:55Z
- 상태: **설계 완료, 실행 보류**
- 범위: 콘텐츠 가설 하나의 관찰 계약. 커뮤니티·제품·해외 확장은 포함하지 않는다.

## 실행 전 승인 경계

이 문서는 자동 게시·예약·발송·스케줄 생성을 하지 않는다. 공개 게시, 댓글/DM 응답, 외부 폼, 광고, 영어권 발송, 계정 권한 변경, 개인정보 수집은 모두 사용자 승인이 있어야만 별도 실행 Intent에서 검토한다. 승인이 없으면 결과는 `no-data → Hold`다.

## 최소 단위와 기록 양식

각 승인된 회차는 근거가 있는 저장물 하나를 아래 세 줄로만 다시 쓴다.

1. 원래 왜 남겼는가
2. 지금 왜 다시 보았는가
3. 다음 선택에 어떻게 쓸 것인가

기록표에는 회차 코드·소재 유형·세 줄의 존재 여부·비식별 집계값만 남긴다. 계정명·핸들·URL·원문 댓글·DM·스크린샷·연락처·프로필은 수집하거나 보관하지 않는다.

## 사전 고정 측정과 해석

| 신호 | 비식별 기록 방식 | 콘텐츠에 대해 말할 수 있는 것 | 말할 수 없는 것 |
| --- | --- | --- | --- |
| 저장 집계 | 승인 플랫폼이 제공한 회차별 수치만 | 관심의 보조 신호 | 커뮤니티 가입·제품 수요·지불 의향 |
| 구체 반응 | 항목·문제·맥락 중 둘 이상 언급 여부만 코드화 | 다음 소재·약속을 조정할 단서 | 일반적 호감·성장·인과 효과 |
| 자발적 적용/다음 편 요청 | 적용 또는 요청의 존재만 코드화 | 반복 소재를 유지할 제한적 근거 | 커뮤니티 수요 또는 기능 요구 |

## 판단 규칙

- 관찰값이 없으면 `no-data → Hold`; 발행 빈도·공개 범위·스트릭·보상으로 보정하지 않는다.
- 독립적으로 반복되는 콘텐츠 신호가 있어도 **콘텐츠 약속 또는 소재**만 조정한다.
- 커뮤니티 전환에는 별도 Intent·승인·옵트인·모더레이션·보존/삭제 기준이 필요하다.
- 제품 전환에는 콘텐츠 신호와 분리된 반복 문제·대안 대비 불편·지속 사용 또는 교환 의향의 증거가 필요하다.

## 보존·삭제 계약

승인된 실행 전, 비식별 기록의 보존 기간·접근자·삭제 절차를 해당 실행 Intent에 고정한다. 원문 또는 식별 가능한 자료가 들어오면 기록하지 않고 삭제 경로를 적용한다.

## T3.1 결론

검증할 것은 ‘저장한 항목을 다시 써 다음 선택 기준으로 남기는 콘텐츠 약속’뿐이다. 이 문서는 실험 실행 결과나 유입·커뮤니티·제품 적합을 주장하지 않는다.
