# Virtue 결과 카드 직후 수동 감탄 vs 자기화 행동 판독표

- intent: `marketing-49`

- scope: docs-only / first-user observation

## 1. 왜 이 표가 필요한가

ChartMogul 노트의 핵심은 AI 제품이 첫 산출물을 매우 빨리 보여줄수록, 사용자가 "와, 신기하다"에서 멈출 위험이 커진다는 점이다. 이 경우 대시보드에서는 activation처럼 보일 수 있지만, 반복 사용이나 자기 맥락 편입으로 이어졌는지는 약하다.

Virtue에서는 이 위험이 특히 `deed_judged` 직후에 나타난다. 결과 카드가 빠른 첫 가치를 만들 수 있지만, 성찰형 제품의 진짜 신호는 사용자가 결과를 자기 말로 받아들이거나 거절하고, 저장/재작성/선택/다음 기록 의도로 옮기는지에 있다.

## 2. 기존 기준은 유지한다

이 문서는 first value 매핑을 바꾸지 않는다.

| 잡 | 기존 first value | 이번 판독의 역할 |
|---|---|---|
| J1 기록형 | `deed_saved` | 결과를 저장할 만큼 자기 기록으로 받아들였는지 본다. |
| J2 누적형 | `deed_saved` | 오늘 결과가 누적 맥락으로 이어지는지 본다. |
| J3 AI 호기심형 | `deed_judged` | 저장 없이 끝나도 정상 완료일 수 있으므로, 정상 무저장과 수동 감탄을 분리한다. |
| J4 회고형 | `deed_saved` | 결과가 회고 문장으로 남을 만큼 소유됐는지 본다. |

## 3. 결과 직후 행동 판독표

첫 10명 관찰에서는 `deed_judged` 직후 30-60초를 별도 판독 단위로 본다. 신규 이벤트를 만들지 않고, 관찰자 수기 메모나 인터뷰 답변으로만 태그한다.

| 태그 | 행동 신호 | 판독 | 기록 문장 예시 |
|---|---|---|---|
| OWN-SAVE | 결과를 읽고 저장한다. | 자기화 강함. J1/J2/J4의 기본 first value 도달. | "읽고 바로 저장했다. 결과 문장을 자기 기록으로 받아들임." |
| OWN-EDIT | 메모를 고치거나 다음 기록에서 바꾸고 싶은 점을 말한다. | 자기화 강함. AI 출력이 사용자 맥락으로 들어감. | "결과를 보고 '이 부분은 다르게 쓰고 싶다'고 말함." |
| OWN-CHOOSE | reroll/재시도 뒤 하나를 고르거나, 왜 이 결과가 맞는지 설명한다. | 자기화 중간-강함. 선택권이 살아 있음. | "두 번째 결과를 고르고 이유를 자기 말로 설명함." |
| OWN-SAY | 결과를 자기 말로 다시 설명한다. | 자기화 신호. 저장 전이라도 retention 후보. | "AI가 한 말을 '내가 오늘 이런 걸 한 거네'로 바꿔 말함." |
| J3-NORMAL-NOSAVE | J3 사용자가 AI 결과를 확인하고 저장 없이 닫는다. | 정상 완료 가능. 호기심 잡은 `deed_judged`가 first value다. | "결과만 확인하고 종료. 불만/혼란 없이 호기심 충족으로 보임." |
| PASSIVE-WOW | "신기하다/좋다" 반응은 있지만 저장, 선택, 설명, 다음 행동이 없다. | 수동 감탄. activation처럼 보이지만 retention 신호 약함. | "감탄 후 바로 이탈. 자기 말 설명이나 저장 없음." |
| FRICTION | 결과를 이해하지 못하거나, 저장/다음 행동 전 막힌다. | 마찰 또는 가용성 문제. value 부재로 단정하지 않음. | "결과 의미를 묻고 멈춤. 버튼/문장/지연 원인 분리 필요." |

## 4. 첫 사용자 관찰표에 추가할 수기 칸

기존 first-user baseline과 design-user ask script에 아래 4칸만 붙인다. 새 계측이나 세션 리플레이는 만들지 않는다.

| 칸 | 질문 | 허용 답 |
|---|---|---|
| result_after_action | 결과 직후 무엇을 했나? | 저장 / 재작성 / 선택 / 자기 말 설명 / 저장 없는 정상 종료 / 수동 감탄 / 마찰 |
| own_words | AI 결과를 자기 말로 어떻게 설명했나? | 가능한 한 원문 그대로 손기록 |
| final_choice | 결과를 받아들였나, 바꾸고 싶었나, 무시했나? | accept / edit / ignore / unsure |
| next_intent | 다음 기록이나 재방문 의도를 말했나? | yes 원문 / no / unclear |

## 5. 후속 질문 후보

첫 세션 직후 묻는 질문은 사용자를 압박하지 않도록 짧게 둔다.

1. "방금 결과에서 그대로 두고 싶은 부분이 있었나요?"
2. "바꾸고 싶은 표현이나 빠진 맥락이 있었나요?"
3. "이 결과를 저장한다면, 나중에 어떤 용도로 다시 보고 싶으세요?"
4. "저장하지 않았다면, 이미 충분해서인지 아직 내 말 같지 않아서인지 어느 쪽에 가까우세요?"

## 6. 승인 경계

- 허용: 내부 문서, 수기 관찰표, 인터뷰 질문 후보, 첫 10명 관찰 기준.
- 금지: 신규 이벤트/속성, tracking/privacy 변경, dashboard/session replay 추가, 공개 카피 변경, DM/메일/알림 발송, 배포, 가격/결제/광고/외부 액션.
- future approval-needed: 이 판독표를 실제 제품 카피, 온보딩 UI, PostHog 이벤트, 자동 리마인드, 공개 모집 문구로 옮기는 모든 작업.

## 7. 다음 Marketer 규칙

AI 결과 카드가 빠르게 감탄을 만들었다고 곧바로 activation으로 보지 않는다. `deed_judged` 이후 사용자가 결과를 자기 말, 선택, 저장, 다음 의도로 옮겼는지 먼저 본다. 특히 J3의 저장 없는 정상 완료와 PASSIVE-WOW를 분리해야 한다.
