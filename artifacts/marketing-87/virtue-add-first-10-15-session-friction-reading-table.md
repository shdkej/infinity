## 목적

프리런치 단계의 작은 `deed_judged → deed_saved` 갭을 곧바로 실패로 세지 않고, `/add` 첫 10~15세션을 같은 기준으로 읽기 위한 1장 판독표입니다. 핵심은 `공통 UX 마찰`, `J3 자연 종료`, `조용한 실패`, `다음 행동 불명확`을 구분하는 것입니다.

## 이벤트 해석 계약

| 구간 | 의미 | 바로 실패로 보면 안 되는 이유 |
|---|---|---|
| `add_flow_started` | 사용자가 `/add`를 시작함 | 진입만으로 intent 품질을 단정할 수 없음 |
| `deed_judge_attempted` | 판단 요청을 실제로 보냄 | 입력 완료까지는 갔지만 응답/이해/로딩 문제가 남아 있을 수 있음 |
| `deed_judged` | AI 결과를 받음 | J3는 여기서 first value가 끝날 수 있음 |
| `deed_saved` | 결과를 저장함 | J1/J2/J4에선 강한 성공 신호지만, 모든 세션의 필수 종료는 아님 |

## 세션별 판독 순서

1. 이벤트 순서를 본다: `add_flow_started → deed_judge_attempted → deed_judged → deed_saved`.
2. replay에서 멈춘 지점을 확인한다.
3. 아래 4개 분류 중 하나를 먼저 고른다.
4. 같은 세션에 보조 신호가 있으면 `보조 메모`에 남긴다.
5. 10개를 모두 읽은 뒤, 개별 실패율보다 `반복 마찰 패턴`이 있는지를 본다.

## 4칸 분류표

| 분류 | 판정 기준 | replay에서 볼 질문 | 권장 해석 |
|---|---|---|---|
| 공통 UX 마찰 | 여러 세션이 같은 단계에서 반복 정지 | 같은 화면/문구/버튼 앞에서 멈추는가? 입력 후 다음 행동을 못 찾는가? | 퍼널 실패보다 UX 마찰 후보로 본다 |
| J3 자연 종료 | `deed_judged`까지 갔고 저장 없이 종료 | 사용자가 결과를 읽고 스크롤/정지 후 이탈했는가? 저장 CTA를 찾지 못한 흔적보다 "확인 후 종료" 흐름에 가까운가? | 정상 완료 후보로 분리한다 |
| 조용한 실패 | 응답 없음, 로딩 정체, 에러, 예상 밖 이탈 | 시도 후 화면 무반응이 있었는가? 재시도/뒤로가기/새로고침이 반복됐는가? | UX보다 기술/상태 이슈 우선 점검 |
| 다음 행동 불명확 | 결과는 봤지만 저장/복귀/다음 행동이 모호 | 결과 후 사용자가 머뭇거리거나 여러 UI를 탐색했는가? 저장 이유나 다음 행동이 읽히지 않았는가? | copy/bridge 문제 후보로 본다 |

## replay 관찰 질문

### A. 공통 마찰 확인

- 같은 단계에서 2회 이상 반복 정지가 보이는가?
- 특정 문장, 버튼, 입력 방식 앞에서 머뭇거림이 반복되는가?
- 저장 전이 아니라 판단 요청 전에서 더 자주 막히는가?

### B. J3 자연 종료 확인

- 사용자가 애초에 "AI가 어떻게 볼지"만 확인하려는 흐름처럼 보이는가?
- 결과를 읽은 뒤 별도 탐색 없이 세션이 차분하게 끝나는가?
- 저장 CTA를 놓친 흔적보다 "목적 달성 후 종료"에 가까운가?

### C. 조용한 실패 확인

- 로딩 스피너, 무반응, 에러성 정지 후 이탈하는가?
- 같은 버튼을 반복 탭하거나 새로고침/뒤로가기를 하는가?
- 기술 상태 문제 없이는 설명하기 어려운 비정상 패턴이 있는가?

### D. 다음 행동 불명확 확인

- 결과를 본 뒤 저장/홈 복귀/다음 행동 중 어디로 가야 하는지 탐색하는가?
- footer/보조 문구를 읽고도 움직임이 없는가?
- 사용자가 value는 받았지만 "그래서 이제 뭘 하지?" 상태로 보이는가?

## 판독 규칙

- `deed_judged` 후 저장이 없다고 자동 실패로 기록하지 않는다.
- J3 후보 세션은 먼저 `자연 종료` 가능성을 본 뒤, 명백한 머뭇거림이 있을 때만 `다음 행동 불명확`로 내린다.
- 같은 단계 정지가 3회 이상 반복되면 개별 세션 해석보다 `공통 UX 마찰`을 우선 원인으로 본다.
- 조용한 실패가 1회라도 명확하면 copy 실험보다 기술 상태 확인을 먼저 둔다.
- 첫 10~15세션에서는 전환율 요약보다 `반복 패턴 1~2개`를 찾는 것이 목적이다.

## 이번 판독표로 가능한 다음 행동

1. replay 10건을 이 표로 읽고, 4분류 중 어디가 가장 자주 나오는지 집계한다.
2. `다음 행동 불명확`이 반복되면 `/add` 결과 카드와 저장 직전 bridge 문구를 다시 검토한다.
3. `공통 UX 마찰`이 반복되면 문구보다 해당 단계의 UI friction을 우선 점검한다.
4. `J3 자연 종료` 비율이 높으면 `judged but not saved`를 실패 KPI로 쓰지 않는다.
