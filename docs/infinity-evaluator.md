# Infinity 운영 품질 평가

평가는 다음 실행에서 바꿀 판단을 찾는 작업입니다. 이 문서가 평가 기준을 소유하며, 사건별 결과는 해당 실행의 report/artifact에 남깁니다.

## 읽을 범위

현재 `INTENTS.yaml`과 최근 heartbeat/report 1~2개부터 확인합니다. 지금 판단을 바꿀 근거가 있을 때만 관련 Archive·trace·artifact를 추가로 읽습니다. 과거 평가 전체를 매번 읽지 않습니다. 상태 전이 절차는 [heartbeat](../heartbeat.md), 완료 형식은 [산출물 규칙](../ARTIFACT_RULES.md)을 따릅니다.

## 평가 기준

| 항목 | 확인할 증거 |
| --- | --- |
| 접수·착수 | Inbox 체류 이유, 목표·완료 기준·승인 경계, 중복 여부 |
| 동시성·대기 | 프로젝트 충돌, Active 한도, 대기 담당·재개 조건 |
| 결과·전달 | 최종 산출물·Report·원격 검증, 실제 화면의 카드·결과 링크 |
| 상태 정합성 | YAML 원장·Archive·trace의 ID·상태·날짜·후속 작업 연결 |
| 반복 실패 | 새로운 근거·대안 없이 같은 차단을 되풀이하는지 |
| 운영 부담 | no-op commit·리포트·중복 문서·불필요한 알림을 만드는지 |

## 반복 운영 학습

- 차단 전에 안전한 대안 경로를 확인합니다. 한 도구의 실패를 전체 환경의 한계로 일반화하지 않습니다.
- 같은 차단이 반복되면 대안·사용자 결정·프로토콜 수정 중 하나로 연결합니다.
- 승인 요청 처리 전 Prompt Archive의 최신 기준과 현재 gate·Intent를 확인합니다.
- 파일 생성만으로 끝내지 않고 사용자가 결과를 열어 다음 판단을 할 수 있는지 확인합니다.

## 결과를 남기는 법

관찰한 문제, 직접 근거, 다음 실행에서 바꿀 행동만 한국어로 짧게 씁니다. 한 번의 사건을 장기 규칙으로 일반화하지 않습니다. 반복되어 절차를 바꿀 필요가 생기면 [README의 문서 지도](../README.md#작업별-읽을-문서)에서 소유 문서를 찾아 수정하고 평가 본문을 여러 곳에 복제하지 않습니다. evaluator는 사용자 채팅으로 메시지를 보내지 않습니다.
